# Step 0: ip-sources

## 배경

phase 73은 네트워크 과목의 `ip-protocol`(IP와 단편화)·`arp`(ARP)·`icmp`(ICMP, IGMP 포함)를 만든다. 전체 계획과 결정은 `phases/73-network-ip-arp-icmp/guide.md`에 있다.
step 2~7이 `ip-protocol`의 개념 12개를 쓰기 전에, **이 step은 그 개념들이 쓸 사실 가운데 강의 밖이거나 강의가 틀렸을 수 있는 것을 표준 문서로 확인하고 출처 문서에 남긴다.**
데이터·코드는 고치지 않는다. 뒤 step은 이 step이 남긴 기록과 summary를 보고 무엇을 쓰고 무엇을 쓰지 않을지 정한다.

`ip-protocol`은 기출 29문항 가운데 19문항이 IPv6다. 강의는 IPv6를 주소 크기·기본 헤더·확장 헤더만 보여 주므로, 기출이 묻는 IPv6 사실(주소 표기와 축약, 주소 자동 설정,
브로드캐스트가 없다는 것, Hop Limit·트래픽 클래스, IPv4와 함께 쓰는 방법)은 **이 step이 확인한 것만** 뒤 step이 쓸 수 있다.

### 2. `docs/source/network/standards.md` — 확인한 사실을 더한다

- 기존 항목의 형식을 따른다: `## (phase 73) <문서 이름> — <절 제목>`, URL 한 줄, 직접 쓴 사실 한 줄씩 끝에 `— §절 번호`, 「쓰인 곳」.
  **같은 RFC의 기존 항목(RFC 791·RFC 8200·RFC 1122·RFC 1812 등)이 있으면 새 항목을 만들지 말고 그 항목에 「(phase 73)」을 붙인 줄로 더한다.**
  머리말의 「(phase 72 step 8)」 설명 다음 줄에 「(phase 73)」이 무엇인지(이 phase의 IP·ARP·ICMP 사실, 확인한 날) 한 줄을 더한다.
- 폐기된 RFC(RFC 1883 등)를 쓰면 항목 제목에 `[폐기, RFC xxxx로 대체 — 역사 기록으로만 쓴다]`를 붙인다(RFC 1631 항목이 본보기).
- 「쓰인 곳」에는 아직 개념 id가 없으므로 **쓰일 개념 id**(`ip-protocol.mtu` 등)와 수정 이력·exam-notes 번호를 적는다.

### 3. `docs/source/network/lecture-outline.md` — 수정 이력

- 확인 결과 강의가 표준과 다르거나 오해를 부르게 줄여 말했으면 `### L33 — …`부터 번호를 이어 「강의 수정 이력」 끝에 더한다. 형식은 L3·L4와 같다 —
  강의(직접 쓴 말)·표준(직접 쓴 말)·근거(문서와 절, URL)·처리(**고쳐 쓴다 / 한정해 쓴다 / 쓰지 않는다**).
  제목 끝에는 `[phase 73에서 찾음]`을 붙인다. 「설계 때 받은 후보」 표는 phase 69의 기록이라 고치지 않는다.
- 「강의 수정 이력」 머리의 「phase 72 step 1에서 …」 문단 뒤에 「phase 73 step 0에서 …」 문단을 더해 무엇을 더했는지(없으면 「Ch3-1에서 새로 찾은 것 없음」)를 적는다.
- 「강의별 정리」의 Ch3-1 절에서 해당 줄 끝에 `⚠ L번호`를 단다(L3·L4처럼). 줄의 내용은 강의가 말한 것 그대로 둔다.
- 확인 결과 강의가 맞으면 수정 이력을 만들지 않고 summary에 「확인 결과 강의가 맞다」로 적는다.

### 4. `docs/source/network/exam-notes.md` — 시험의 답이 표준과 다르거나 표준에 없는 곳

이 주제의 기출 문항(`data.txt`의 `ip-protocol` 줄)이 정답으로 보는 것이 허용한 출처에 없거나 다르면 `## E9 — …`부터 번호를 이어 더한다(E1~E8 형식). 표준에 있으면 항목을 만들지 않는다.
형식은 E8을 따르고(시험·표준·처리·쓰인 곳), E4 앞의 「E4~E8은 phase 72 step 1에서 …」 문단처럼 이 step이 더한 항목을 소개하는 문단을 E9 앞에 둔다(확인한 날 포함).

다음 셋은 미리 본 후보다 — 확인한 뒤 해당하면 항목으로 남긴다.

- **IPv6 헤더의 「Priority」**([기출 2024-11-03 #3]): 시험이 옛 이름과 옛 설명을 쓴다. 처리는 ADR-059의 「시험이 옛 방식을 묻고 공식 문서가 새 방식을 말할 때」와 같다 —
  본문은 지금 이름(트래픽 클래스)을 쓰고 「자격시험은 옛 이름 Priority로 묻기도 한다」를 덧붙인다.
- **TTL의 단위**([기출 2026-05-17 #10]): 표준은 초로 정의하지만 시험은 ping 결과의 TTL을 초로 읽는 것을 틀렸다고 본다. 둘이 실제로 충돌하는지(표준도 「최소 1씩 줄이므로 실제로는 홉 수의 상한」이라 하는지) 보고,
  충돌하지 않으면 항목을 만들지 말고 summary에 본문이 어떻게 쓰면 되는지 적는다.
- **정답 키 오류로 보이는 문항**([기출 2024-05-19 #1] — DF 플래그): exam-notes의 처리 「본문은 표준을 쓰고 자격시험 줄을 덧붙인다」를 그대로 따르면 틀린 사실(조각을 DF 플래그로 구별한다)을 시험의 시각으로 가르치게 된다.
  **이 항목은 「처리」를 「본문은 표준(식별자)을 쓴다. 한 회차의 정답 키 오류로 보여 「자격시험은」 줄을 쓰지 않는다 — 사용자 확인 대상」으로 적고**, 본문·문항에서 이 문항의 시각을 가르치지 않는다.
  summary의 「사용자 확인」 칸에 이 판단을 적는다. ADR-057의 처리 규칙을 바꾸는 것이 아니라 그 규칙이 다루지 않은 경우(정답 키 오류)를 기록만 하는 것이다.

### 5. summary — 뒤 step이 이것을 보고 쓴다

`ip-protocol`의 개념 12개마다 한 줄씩: **무엇을 쓸 수 있는지(출처와 함께), 무엇을 고쳐 쓰는지(L번호), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호)**.
위 표의 a~n마다 결과(확인함/강의가 맞음/못 찾음)와 근거 문서를 적는다. 못 찾은 것은 무엇을 어디서 찾아봤는지 적는다. 끝에 「사용자 확인」 칸을 둔다(없으면 「없음」).
