# Step 1: switch-sources

## 배경

phase 72는 네트워크 과목의 `ethernet`(이더넷과 프레임)과 `hub-switch-vlan`(허브·스위치·VLAN)을 만든다. 전체 계획과 결정은 `phases/72-network-ethernet-switch/guide.md`에 있다.
step 0이 `ethernet`의 출처를 확인했다(그 summary는 `phases/72-network-ethernet-switch/index.json`의 step 0). **이 step은 `hub-switch-vlan`의 개념 12개가 쓸 사실 가운데
강의 밖이거나 강의가 틀렸을 수 있는 것을 표준·공식 문서로 확인하고 출처 문서에 남긴다.** 데이터·코드는 고치지 않는다.

이 step에는 사용자 결정 둘이 걸려 있다(다시 묻지 마라).

- 사용자는 배포된 1장을 보고 「강의 들을 때 허브부터 설명해준 거 같아. 그러면서 허브는 요즘 사용하지 않는다는 말도」라고 했다. 「허브는 요즘 안 쓴다」는 슬라이드 글자에 없고 영상 발언으로 보인다.
  **표준 쪽 근거를 찾았을 때만 본문에 쓴다**(2026-10-28 결정).
- VTP는 시스코가 만든 프로토콜이다. 사용자가 **cisco.com의 제품 문서(설정 가이드 같은 것. 학습·마케팅 페이지는 아니다)를 허용 출처에 더하고** 개념 20 `vlan-tagging`의 한 문단으로 쓰기로 했다(2026-10-28, 권장안 A).
  ADR-059 「목록에 없는 곳은 그 주제를 만드는 phase의 설계 때 같은 기준(그 기술을 만든 곳의 공식 문서)으로 판단한다」에 따른 것이다.

## 작업

### 1. 확인할 것 — 하나씩 허용한 출처를 실제로 열어(WebFetch) 확인한다

IEEE 802.3·802.1 표준 본문은 허용한 곳에서 무료로 열리지 않는 경우가 많다. 작업 그룹이 `ieee802.org`에 올린 초안·유지 보수 요청·회의 자료·작업 그룹 페이지가 그 절의 본문이나 내용을 싣고 있으면
그것을 근거로 쓰고 **어떤 종류의 문서인지**(표준 본문을 실은 초안인지, 작업 그룹이 승인한 유지 보수 요청인지, 투표 의견 기록인지)를 항목에 적는다.
IETF RFC(예: RFC 4188 Bridge MIB, RFC 4363 Q-BRIDGE MIB, RFC 7348 VXLAN)와 IANA 레지스트리도 IEEE 802.1의 개념을 풀이하므로 쓸 수 있다.

| # | 개념 | 확인할 것 | 볼 곳(예) |
|---|---|---|---|
| a | `hub` | 허브가 표준에서 무엇인지 — 포트가 여럿인 리피터인지, 물리 계층에서 받은 신호를 다른 모든 포트로 다시 내보내는지 | IEEE 802.3 Clause 9(10 Mb/s 리피터)·Clause 27(100 Mb/s 리피터) |
| b | `hub` | **「허브는 요즘 안 쓴다」의 근거** — IEEE 802.3이 리피터·반이중(공유 매체)을 「새 설치에 권하지 않는다」거나 더 유지 보수하지 않는다고 정했는지, 그것이 어느 문서(표준 본문의 주석, 승인된 유지 보수 요청)에 있는지. 10기가비트 이상 이더넷이 전이중만 쓰는지(step 0이 802.3ae를 봤으면 그 결과). 설계 때 본 단서: [802.3bh 의견 기록](https://www.ieee802.org/3/bh/comments/P802d3_802d3_bh_D3p0_All_Clause.pdf), [802.3ay 의견 기록](https://ieee802.org/3/axay/comments/D1.0/802.3ay_D1p0.pdf), [802.3 유지 보수 요청 목록](https://www.ieee802.org/3/maint/requests/all.html) — 의견 기록은 제안일 뿐이니 채택된 문구를 찾는다 | `ieee802.org/3/maint`, 802.3 초안 |
| c | `duplex`·`collision-domain` | 반이중·전이중의 정의, 충돌 도메인의 정의(리피터로 이은 장치는 같은 충돌 도메인, 브리지로 나뉜 장치는 다른 충돌 도메인인지), 전이중 링크에서는 충돌이 없는지 | IEEE 802.3 정의 절(1.4), Clause 4, Annex 4A |
| d | `collision-domain` | 기출이 맞는 설명으로 보는 「충돌 도메인이 작을수록 좋다」의 근거가 있는지(없으면 E 항목) | 위와 같음 |
| e | `csma-cd` | 캐리어 감지 후 기다림, 충돌 감지, 잼 신호, 무작위로 기다리는 재전송(절단 이진 지수 백오프), 재시도 한도. 전이중에서는 CSMA/CD를 쓰지 않는지. 토큰을 쓰지 않는다는 것(토큰 방식은 IEEE 802.5 토큰 링)은 이름만 필요하다 | IEEE 802.3 Clause 4 |
| f | `switch` | 표준 문서가 스위치를 「브리지(MAC Bridge)」라 부르는지, 데이터 링크 계층에서 목적지 MAC 주소로 전달하는지. 「L2 스위치」라는 이름은 기출이 쓰는 말이다 | IEEE 802.1D·802.1Q 소개, RFC 4188 §1~§3 |
| g | `mac-address-table` | 출발지 MAC 주소와 들어온 포트로 항목을 배우는지, 에이징 기본값 300초(설계 때 RFC 4188의 `dot1dTpAgingTime`에서 「802.1D-1998이 300초를 권한다」를 봤다) | RFC 4188 §4 `dot1dTpAgingTime`·`dot1dTpFdbPort` |
| h | `flooding-forwarding-filtering` | 목적지를 모르는 프레임과 브로드캐스트 프레임을 받은 포트를 뺀 모든 포트로 내보내는지, 목적지가 받은 포트 쪽이면 내보내지 않는지(강의 p93–p97은 그림으로만 보인다) | IEEE 802.1D·802.1Q의 전달 과정, RFC 4188 |
| i | `stp` | 스위치를 고리로 이으면 프레임이 끝없이 도는지(기출은 「과도한 브로드캐스트 트래픽」), STP가 일부 포트를 막아 고리 없는 경로를 만드는지, 쓰던 길이 끊기면 막았던 포트를 쓰는지. 포트 상태(차단·학습·전달) | IEEE 802.1D 소개·작업 그룹 페이지, RFC 4188 `dot1dStpPortState` |
| j | `broadcast-domain` | 「브로드캐스트 도메인」이라는 말과 그 뜻, VLAN이 2계층 네트워크를 여러 브로드캐스트 도메인으로 나눈다는 것(설계 때 RFC 7348 §3.1에서 봤다), 라우터가 링크 계층 브로드캐스트를 넘기지 않는지 | RFC 7348 §3.1, `standards.md`의 RFC 919, RFC 1812 |
| k | `vlan` | VLAN의 정의, VLAN 사이의 통신이 라우터 같은 3계층 장비를 거치는지, VLAN마다 다른 보안 정책을 줄 수 있는지(둘 다 기출) | IEEE 802.1Q 소개, RFC 7348, NIST(`csrc.nist.gov`)의 네트워크 분리 문서 |
| l | `vlan-membership` | 포트로 VLAN을 정하는 방식(802.1Q의 PVID)과, 강의가 말하는 MAC 주소로 정하는 방식이 표준 어디에 있는지(없으면 강의 사실로만 쓴다고 적는다) | IEEE 802.1Q, RFC 4363 |
| m | `vlan-tagging` | 802.1Q 태그 — 크기(4옥텟), 자리(출발지 MAC 주소 뒤), TPID 값 0x8100(IANA 레지스트리의 이름), VLAN ID 12비트(RFC 7348 §3.1)와 쓸 수 있는 값의 범위. **「트렁크」라는 말**이 허용한 출처에 있는지(없으면 E 항목), 태그를 붙여 보내는 포트·붙이지 않는 포트 | IEEE 802.1Q, IANA IEEE 802 Numbers, RFC 4363, RFC 7348 |
| n | `vlan-tagging` | **VTP** — 무엇을 하는지(같은 VTP 도메인의 스위치들이 트렁크로 VLAN 설정을 퍼뜨려 맞추는지), 모드 셋(서버·클라이언트·트랜스페어런트)과 VTP 버전 3의 off 모드. 시스코 제품 문서의 어느 문서·판을 기준으로 읽었는지 적는다 | `cisco.com`의 Catalyst 스위치 설정 가이드(제품 문서) |

빠진 것을 읽다가 찾으면 더한다. **강의 p89의 스위치 충돌 도메인 표현**(「목적지 호스트가 연결된 곳만 충돌 도메인에 속한다」)이 표준의 충돌 도메인 정의와 맞는지 따로 본다.
강의 Ch2-2·Ch2-3에서 표준과 다르거나 오해를 부르게 줄여 말한 곳이 더 있으면 같은 방법으로 확인한다.

### 2. 허용 출처에 cisco.com을 더한다 — 쓰기 전에 먼저

`docs/source/network/CLAUDE.md` 「허용하는 출처」와 `docs/source/network/topic-map.md` 「출처 영역」에 같은 내용으로 한 줄씩 더한다(두 목록은 같은 곳을 말해야 한다).

- 무엇: **스위치 업체 기술 — Cisco 제품 문서(`cisco.com`의 설정 가이드·명령 참조 같은 제품 문서). 학습·마케팅·블로그 페이지는 쓰지 않는다.**
- 왜: VTP처럼 시스코가 만든 기술의 사실은 만든 곳의 공식 문서가 출처다(ADR-059 「목록에 없는 곳」). 사용자 결정 2026-10-28.
- 어디에 쓰는지: 강의 주제 `hub-switch-vlan`의 VTP. `topic-map.md` 「출처 영역」은 강의 밖 주제의 출처를 적는 절이므로, 강의 주제에서 쓴다는 것을 그 줄에 밝힌다.

### 3. `docs/source/network/standards.md` — 확인한 사실을 더한다

- 기존 항목 형식을 따른다: `## (phase 72) <문서 이름> — <절 제목>`, URL, 직접 쓴 사실 한 줄씩 끝에 `— §절 번호`(절 번호가 없는 문서는 절 제목), 「쓰인 곳」에 쓰일 개념 id(`hub-switch-vlan.hub` 등)와 수정 이력 번호.
- step 0이 같은 문서의 항목을 만들었으면 그 항목에 「(phase 72)」 줄로 더한다. 초안·의견 기록·유지 보수 요청을 근거로 쓰면 문서의 종류를 적는다.
- 시스코 문서는 제품 버전마다 달라지므로 어느 제품·판의 문서를 읽었는지 항목에 적는다(ADR-059 「트레이드오프」).

### 4. `docs/source/network/lecture-outline.md` — 수정 이력

- 강의가 표준과 다르거나 오해를 부르게 줄여 말했으면 step 0이 이은 번호 다음부터 `### L… — …`를 「강의 수정 이력」 끝에 더한다. 형식은 L1·L2와 같고 제목 끝에 `[phase 72에서 찾음]`.
  처리는 **고쳐 쓴다 / 한정해 쓴다 / 쓰지 않는다** 가운데 하나다.
- 「강의별 정리」의 Ch2-2·Ch2-3 절에서 해당 줄 끝에 `⚠ L번호`를 단다. 줄의 내용은 강의가 말한 것 그대로 둔다.
- 「허브는 요즘 안 쓴다」는 슬라이드에 없으므로 수정 이력이 아니다 — 근거를 찾았으면 `standards.md`에만 적고, summary에 본문에 쓸 수 있는 문장의 범위를 적는다.

### 5. `docs/source/network/exam-notes.md` — 시험의 답이 표준과 다르거나 표준에 없는 곳

step 0이 이은 번호 다음부터 `## E… — …`로 더한다(E1~E3 형식). 이 주제의 기출이 정답으로 보는 것 가운데 허용한 출처에 없거나 다른 것이 대상이다 —
후보는 「트렁크」라는 용어, VLAN마다 다른 보안 정책, VLAN 사이 통신은 3계층 장비, 「충돌 도메인이 작을수록 좋다」, 「L2 스위치」라는 이름. 출처에 있으면 항목을 만들지 않는다.
기출 문항의 보기 가운데 시험이 맞는 설명으로 두었지만 표준과 다른 것이 있으면(예: CSMA/CD에서 장치가 매체를 살피려고 신호를 주기적으로 보낸다는 보기) 본문이 그것을 가르치지 않도록 항목으로 남긴다.

### 6. summary — 뒤 step이 이것을 보고 쓴다

`hub-switch-vlan`의 개념 12개마다 한 줄씩: **무엇을 쓸 수 있는지(출처와 함께), 무엇을 고쳐 쓰는지(L번호), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호)**.
특히 `hub`에 대해 **「요즘 안 쓴다」를 쓸 수 있는지, 쓴다면 어떤 범위의 문장까지인지**(예: 「IEEE 802.3은 리피터를 새로 설치하는 데 권하지 않는다」)를 분명히 적는다.
위 표의 a~n마다 결과(확인함/강의가 맞음/못 찾음)와 근거 문서를 적는다. 못 찾은 것은 어디서 찾아봤는지 적는다. cisco.com을 더한 두 파일의 줄도 적는다.

## 금지사항

- **`src/`의 데이터·코드·테스트를 고치지 마라.** 이유: 이 step은 출처만 확인한다. 개념은 step 6~11이 쓴다.
- **근거 없이 「허브는 요즘 안 쓴다」를 출처 문서에 사실로 적지 마라. 투표 의견 기록 하나만으로 확정하지 마라.** 이유: 사용자가 근거를 찾은 뒤에만 쓰기로 했다. 의견 기록은 제안이지 결정이 아니다.
- **cisco.com의 학습·마케팅·블로그 페이지를 근거로 쓰지 마라. 시스코 문서를 VTP 밖의 사실(VLAN·트렁크 일반)의 근거로 쓰지 마라.** 이유: 사용자가 허용한 것은 시스코가 만든 기술의 제품 문서다.
  VLAN·태그는 IEEE 802.1Q와 RFC가 정한 것이라 그쪽이 출처다.
- **허용한 출처 밖의 문서를 근거로 쓰지 마라.** 이유: ADR-059.
- **강의·기출·표준·공식 문서의 문장을 옮기지 마라.** 이유: ADR-009·ADR-057.
- **`topic-map.md`의 주제 표·숫자·별점·phase 계획, ADR을 고치지 마라.** 이유: 허용 출처 한 줄을 더하는 것 말고는 이 step의 범위가 아니다. 주제 범위를 바꾸려면 ADR이 필요하다.
