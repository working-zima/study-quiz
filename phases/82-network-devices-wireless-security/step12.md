# Step 12: devices-sources-b

## 배경

phase 82는 네트워크 과목의 `wireless-lan`·`network-devices`·`network-security`를 만든다. 전체 계획과 결정은 `phases/82-network-devices-wireless-security/guide.md`에 있다.
step 13~14가 `network-devices`의 뒤 개념 4개(L4 스위치, L7 스위치, PoE, PXE)를 쓰기 전에,
**이 step은 그 개념들이 쓸 사실을 허용한 출처로 확인하고 출처 문서에 남긴다.** 데이터·코드는 고치지 않는다.

이 네 개념의 사실은 IETF RFC(RFC 3234 — 중간 장치의 분류, RFC 2391 — 부하 분산 NAT, RFC 4578 — PXE의 DHCP 옵션, RFC 1350 — TFTP), IEEE 802.3(PoE — 802.3af·at·bt), learn.microsoft.com(Windows 배포 서비스(WDS)의 PXE, IIS ARR)에서 가져온다(ADR-059).
**「L4 스위치」·「L7 스위치」라는 이름은 표준 용어가 아니다**(guide.md 「배경」) — 이 step이 그 처리를 E 항목으로 정한다.
기출 23문항 가운데 이 step의 네 개념에 걸린 것은 8문항이다 — L4 스위치([기출 2025-08-24 #50]·[기출 2026-08-02 #46]·[기출 2025-11-02 #48]·[기출 2026-02-01 #6]), L7 스위치([기출 2026-02-01 #49]), PoE([기출 2024-05-19 #50]·[기출 2025-11-02 #50]), PXE([기출 2026-05-17 #50]).

## 작업

### 1. 확인할 것 — 하나씩 허용한 출처를 실제로 열어 확인한다

**판을 적는다** — RFC는 번호와 그것을 고친 RFC, IEEE는 표준 번호와 해·상태(802.3af·at·bt가 지금 802.3 본문의 어느 절로 들어갔는지), learn.microsoft.com은 갱신 날짜와 적용 대상. 응답이 느리면 `curl -4`로 다시 받는다.
**한국어 이름**: 학습자에게 보일 이름(전송 계층·응용 계층 부하 분산 장치, 전원 공급 장치(PSE)·전원 수신 장치(PD), 네트워크 부팅 등)을 정하고 고른 까닭을 적는다.

| b | `l7-switch` | 응용 계층 정보(URL·HTTP 헤더·쿠키)로 서버를 고르는 장치를 허용한 출처가 어떻게 설명하는지(RFC 3234 §2.18), 요청을 읽으려면 클라이언트와 먼저 연결을 맺어야 한다는 것·역방향 프록시처럼 동작한다는 것(근거대로 — RFC 9110의 gateway, IIS ARR의 URL 규칙에 따른 라우팅), 포트로 나누기와 상태 확인도 하는지. **「L7 스위치」라는 이름**이 허용한 출처에 있는지 — 없으면 a와 한 E 항목으로 묶어도 된다. **[기출 2026-02-01 #49]**의 정답(「TCP/UDP 헤더만으로 분산한다」가 틀린 말)과 시험이 맞는 말로 두는 보기 셋(교사용 텍스트에서 확인 — 「L2·L3·L4 기능을 포괄한다」 등)이 문서와 맞는지 | RFC 3234 §2.18, RFC 9110 §3.7, learn.microsoft.com의 IIS ARR 「HTTP Load Balancing using Application Request Routing」·URL 재작성 규칙으로 서버 팜에 보내기 문서, ko-kr 판 |

### 2. `docs/source/network/standards.md` — 확인한 사실을 더한다

- step 8과 같은 형식이다: `## (phase 82 step 12) <출처 이름> — <문서 제목들>`, URL 한 줄씩, **판** 한 줄, 직접 쓴 사실 한 줄씩 끝에 `— 절 제목`, 「쓰인 곳」.
  같은 문서의 기존 항목이 있으면(step 8의 RFC 2391·3234, phase 72의 802.3, phase 74의 DHCP, phase 78의 TFTP) 그 항목에 「(phase 82 step 12)」을 붙인 줄로 더한다.
- 항목마다 **한국어 이름** 줄을 둔다. 「쓰인 곳」에는 **쓰일 개념 id**(`network-devices.poe` 등)와 exam-notes 번호를 적는다.
- 머리의 「확인한 날」 문단들 끝에 「(phase 82 step 12)」 줄을 더한다.

### 3. `docs/source/network/exam-notes.md` — 시험의 답이 공식 문서와 다르거나 공식 문서에 없는 곳

이 step의 기출 8문항이 정답으로 보는 것(과 시험이 맞는 말로 두는 보기)이 허용한 출처에 없거나 다르면 앞 step이 더한 번호 다음부터 `## E… — …`로 더한다(E7 형식 — 시험·표준·처리·쓰인 곳).
앞 step의 「phase 82」 문단 뒤에 이 step이 본 문항 수와 더한 항목, 공식 문서와 맞는 문항들을 한 줄씩 짚는 문단을 더한다(확인한 날 포함).

미리 본 것 — 판정은 이 step이 출처를 읽고 한다:
- **「L4 스위치」·「L7 스위치」라는 이름** — 표준에 없으면 E7과 같은 꼴: 본문은 표준의 설명(포트로 나누는 장치·URL로 나누는 장치)을 쓰고, 시험은 이것을 L4·L7 스위치라 부른다는 것을 덧붙인다.
- **L4 스위치의 맞는 보기 「HTTP 헤더까지 분석」**([기출 2025-08-24 #50]·[기출 2026-08-02 #46]) — 포트로 나누는 장치의 설명과 어긋나면 E 항목. 표준과 반대되는 동작을 가르치게 되면 E6처럼 본문에 「자격시험은」 줄도 두지 않는 처리를 고르고 그 까닭을 적는다.
- 「PoE 스위치」·「L7 스위치가 L2·L3·L4 기능을 포괄한다」 같은 시험 쪽 표현이 허용한 출처에 없으면 처리(본문에 쓸지, 「자격시험은」 줄로 쓸지).

### 4. summary — 뒤 step이 이것을 보고 쓴다

`network-devices`의 개념 7~10마다 한 줄씩: **무엇을 쓸 수 있는지(문서·판·절), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호와 그 처리), 한국어 이름**.
위 표의 a~d마다 결과(확인함/못 찾음)와 근거 문서·판을 적는다. 못 찾은 것은 무엇을 어디서 찾아봤는지 적는다.
특히 다음을 개념 step이 그대로 쓸 수 있게 적는다.
- 포트로 나누는 장치의 동작과 LSNAT의 주소 바꾸기 차례(요청과 응답), 세션 유지, 기본 기능 셋의 근거, 「L4 스위치」 이름의 처리.
- URL로 나누는 장치의 동작(연결을 먼저 맺는다·역방향 프록시처럼 — 근거가 있는 만큼), L4의 일도 하는지, 「L7 스위치」 이름과 기출 보기의 처리.
- PoE·PSE·PD의 정의, 802.3af·at·bt의 해와 전력 값(문서의 값), 검출 절차, 「PoE 스위치」의 처리.
- PXE의 설명과 차례(DHCP로 받는 것 → TFTP로 받는 것 → 실행), WDS 한 줄과 지금 판의 상태, PnP·PE를 쓸 수 있는지.
- 기출 판정 줄: L4 넷, L7, PoE 둘, PXE.
끝에 「사용자 확인」 칸을 둔다 — 있으면 적고, 없으면 「없음」.
