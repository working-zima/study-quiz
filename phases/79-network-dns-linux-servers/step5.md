# Step 5: dns-sources-b

## 배경

phase 79는 네트워크 과목의 `dns`(강의 주제)와 `linux-servers`(강의 밖 주제)를 만든다. 전체 계획과 결정은 `phases/79-network-dns-linux-servers/guide.md`에 있다.
step 6~8이 `dns`의 **뒤 개념 6개**(9 DNS 레코드 ~ 14 DNSSEC)를 쓰기 전에, **이 step은 그 개념들이 쓸 사실 가운데 강의 밖이거나 강의가 틀렸을 수 있는 것을 표준·공식 문서로 확인하고 출처 문서에 남긴다.**
데이터·코드는 고치지 않는다. 뒤 step은 이 step이 남긴 기록과 summary를 보고 무엇을 쓰고 무엇을 쓰지 않을지 정한다.

강의는 레코드 유형 다섯(A·AAAA·CNAME·NS·SOA — p348–p350, L15로 고침)과 업체 화면 그림(A·MX·CNAME·TXT)만 다룬다. 나머지는 강의 밖이다.
기출이 뒤 개념 6개에서 묻는 것은 SOA와 그 필드(4회 — 영역 파일의 시작, Refresh, 책임자 메일 표기, 「TTL이 길면 부하」가 틀린 말), CNAME(3회 — 별칭, 서브 도메인 등록이 아니다), 역방향 조회와 PTR(3회),
NS는 메일과 관계없다(MX), TCP와 UDP를 모두 쓰는 응용 프로토콜(2회 — L11), BIND를 운영할 때 UDP 53만 열면 되는 것이 아니다, DNS 라운드 로빈, DNSSEC(무결성과 출처 인증 — 암호화가 아니다)이다.
25문항 가운데 여럿이 Windows Server의 DNS 서버 화면 문맥이다 — 레코드 메뉴 이름과 SOA 필드 이름을 learn.microsoft.com에서 확인한다.

L11·L15는 이미 있다 — 다시 확인하지 않는다. **Linux 서버 설정(`resolv.conf`·BIND의 `named.conf`·Apache·iptables)은 확인하지 않는다**(step 9의 범위). 다만 e에서 DNS 서버의 방화벽에 무엇을 열어야 하는지의 근거는 이 step이 적는다.

### 2. `docs/source/network/lecture-outline.md` — 수정 이력

- 확인 결과 강의가 표준과 다르거나 오해를 부르게 줄여 말했으면 「강의 수정 이력」 끝에 번호를 이어 더한다(step 0이 쓴 마지막 번호 다음 — 지금 마지막 번호를 보고 잇는다). 형식은 L43~L47과 같고, 제목 끝에 `[phase 79에서 찾음]`을 붙인다.
- 「강의 수정 이력」 머리의 「phase 79 step 0에서 …」 문단 뒤에 「phase 79 step 5에서 …」 문단을 더해 무엇을 더했는지와 표준과 어긋나지 않은 강의 사실을 적는다.
- 「강의별 정리」의 Ch5-1 절에서 해당 줄 끝에 `⚠ L번호`를 단다. 줄의 내용은 강의가 말한 것 그대로 둔다.
- 확인 결과 강의가 맞으면 수정 이력을 만들지 않고 summary에 「확인 결과 강의가 맞다」로 적는다.

### 3. `docs/source/network/standards.md` — 확인한 사실을 더한다

- 기존 항목의 형식을 따른다: `## (phase 79 step 5) <문서 이름> — <제목>`, URL 한 줄, **상태나 읽은 판** 한 줄, 직접 쓴 사실 한 줄씩 끝에 `— §절 번호`, 「쓰인 곳」.
  **같은 문서의 기존 항목(RFC 1034·1035·7766·5321, step 0이 만든 RFC 9499·learn.microsoft.com DNS 항목 등)이 있으면 새 항목을 만들지 말고 그 항목에 「(phase 79 step 5)」를 붙인 줄로 더한다.**
- 「쓰인 곳」에는 **쓰일 개념 id**(`dns.soa-record` 등)와 수정 이력·exam-notes 번호를 적는다.
- 머리의 「확인한 날」 문단들 끝에 「(phase 79 step 5)」가 붙은 줄과 항목이 무엇인지 한 문장을 더한다.

### 4. `docs/source/network/exam-notes.md` — 시험의 답이 표준과 다르거나 표준에 없는 곳

위 기출 문항이 정답으로 보는 것(과 「옳지 않은 것」을 고르는 문항에서 맞는 말로 두는 보기)이 허용한 출처에 없거나 다르면 step 0이 더한 마지막 번호 다음부터 `## E… — …`로 이어 더한다(E27~E34 형식).
표준·공식 문서에 있으면 항목을 만들지 않는다. 「phase 79 step 0」 문단처럼 이 step이 본 문항 수와 더한 항목을 소개하고 표준과 맞는 문항들을 한 줄씩 짚는 문단을 둔다(확인한 날 포함).

미리 본 것 — 판정은 이 step이 출처를 읽고 한다:
- [기출 2024-11-03 #43]의 맞는 보기 「영역 파일은 늘 SOA로 시작한다」, 「Refresh는 주 서버와 보조 서버의 동기 주기」와 [기출 2025-08-24 #39]의 맞는 보기 셋(일련번호·주 서버·새로 고침 간격)이 b와 맞는지. 「주 서버 : 해당 영역이 초기에 설정되는 서버」 같은 Windows 화면 설명은 learn.microsoft.com과 대조한다.

- [기출 2025-05-25 #42]가 「방화벽에서 UDP 53번만 열면 된다」를 틀린 말로 둔다 — e와 맞을 것이다. 같은 문항의 맞는 보기(`iptables`로 방화벽 설정, `rpm -qa | grep bind`로 설치 확인, `named-checkconf`)는 step 9가 본다 — 이 step은 판정하지 않는다.

### 5. summary — 뒤 step이 이것을 보고 쓴다

`dns`의 뒤 개념 6개마다 한 줄씩: **무엇을 쓸 수 있는지(출처와 절), 무엇을 고쳐 쓰는지(L번호), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호)**.
위 표의 a~f마다 결과(확인함/강의가 맞음/못 찾음)와 근거 문서·상태·판을 적는다. 못 찾은 것은 무엇을 어디서 찾아봤는지 적는다.
특히 다음을 개념 step이 그대로 쓸 수 있게 적는다.
- 레코드 유형 표: 유형 이름, 풀어 쓴 이름(근거에 있을 때만), 데이터, Windows 메뉴 이름(한국어 확인 여부 표시), 근거 절.
- 영역 파일의 레코드 한 줄 꼴과 SOA 한 줄(여러 줄) 꼴 — 칸의 차례와 생략 규칙(값은 guide.md 「예시 값」). SOA의 예시 수(일련번호·간격들)를 이 step이 정해 적는다 — 권고값처럼 읽히지 않는 값으로.
- SOA 필드 표: 필드 이름, 뜻, 단위, Windows 필드 이름.
- 역방향 조회 이름 만들기의 단계(주소 → 거꾸로 → `in-addr.arpa`).
- DNS가 TCP를 쓰는 때의 목록과 근거.
끝에 「사용자 확인」 칸을 둔다(없으면 「없음」) — 허용한 출처 밖의 문서가 꼭 필요하거나 guide.md의 결정과 맞지 않는 사실을 찾았을 때만 적는다.

## 금지사항

- **`src/`의 데이터·코드·테스트를 고치지 마라.** 이유: 이 step은 출처만 확인한다. 개념은 step 6~8이 쓴다.
- **확인하지 못한 사실을 standards.md·수정 이력에 적지 마라.** 이유: 뒤 step이 이 기록을 근거로 학습자에게 가르친다. 못 찾았으면 못 찾았다고 summary에 적는다.
- **허용한 출처 밖의 문서(위키백과·블로그·자격증 교재·업체 학습 페이지, 도메인 업체의 도움말)를 근거로 쓰지 마라.** 이유: ADR-059. 목록에 없는 곳이 꼭 필요하면 쓰지 말고 summary의 「사용자 확인」에 적는다.
- **강의·기출·표준 문서의 문장을 옮기지 마라.** 이유: ADR-009·ADR-057.
- **기존 항목의 줄을 고치거나 지우지 마라.** 이유: 앞 phase와 step 0의 개념이 그 줄을 근거로 쓴다. 더할 것은 「(phase 79 step 5)」 줄로 더한다.
- **DNSSEC의 키 관리·서명 알고리즘·NSEC, EDNS의 옵션, 다른 레코드 유형(SRV·CAA 등)을 정리하지 마라.** 이유: 기출이 묻지 않는 것을 끌어오지 않는다(ADR-059 「범위」).
- **Linux 서버 설정의 사실을 정리하지 마라.** 이유: step 9의 범위다.
- **`docs/source/network/CLAUDE.md`·`topic-map.md`·`interview-facts.md`를 고치지 마라.** 이유: 이 step이 쓰는 출처는 모두 이미 허용한 곳이고, 면접은 이 개념들을 다루지 않는다.
