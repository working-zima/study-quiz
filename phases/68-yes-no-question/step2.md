# Step 2: yes-no-invariants

## 배경

phase 68은 문항 형식에 **예/아니요**를 더한다(지금까지는 4지선다 단일정답뿐, ADR-005). 주관식은 만들지 않는다. AWS 746문항은 4지선다 그대로이고,
예/아니요 문항을 처음 쓰는 것은 다음 과목(네트워크)이다.

지금까지: step 0이 `src/types/content.ts`에 `Question = ChoiceQuestion | YesNoQuestion`(`YesNoQuestion`은 `format: 'yes-no'`·`answer: boolean`, 예가 정답이면 true)과
채점·섞기를 만들었고, step 1이 `QuizRunner`에서 예/아니요를 가로로 나란히 놓인 두 버튼으로 풀게 했다.

예/아니요 문항은 쓰는 규칙이 있다 — 주장 하나만 묻는다, 이중 부정을 쓰지 않는다, 「항상」「절대」처럼 답을 흘리는 낱말을 쓰지 않는다, 예와 아니요가 대략 반반이다,
아니요 문항의 해설은 맞는 사실을 가르친다. 이 step은 그 가운데 **기계로 잴 수 있는 것만** 과목 불변식으로 둔다. 나머지는 step 3이 ADR-054에 적고 사람이 검수한다.

지금은 어느 과목에도 예/아니요 문항이 없으므로 이 불변식은 빈 집합으로 통과한다. 그래서 **검사가 실제로 위반을 잡는지**를 같은 파일의 테스트로 함께 증명한다.

## 작업

### 1. 검사 함수 — `src/data/index.test.ts` 안

```ts
function yesNoProblems(questions: Question[]): string[]
```

- 예/아니요 문항(`format === 'yes-no'`)**만** 본다. 4지선다 문항에는 어떤 규칙도 걸지 않는다.
- 돌려주는 것은 사람이 읽을 문제 설명 목록이다. 문항이 걸린 규칙은 그 문항 id를 담는다. 문제가 없으면 빈 배열.
- 규칙 셋:
  1. **문제문이 물음표로 끝난다.** `prompt.trimEnd()`가 `?`로 끝나야 한다. 예/아니요 문항은 「~인가요?」처럼 예나 아니요로 대답하는 질문이다.
  2. **문제문에 「항상」「절대」가 없다.** 단순 부분 문자열 검사다. 이런 낱말은 내용과 무관하게 「아니요」를 흘린다.
  3. **예와 아니요가 대략 반반이다.** 넘긴 문항 가운데 예/아니요 문항 수를 `total`, `answer: true` 수를 `yes`, `false` 수를 `no`라 할 때
     `Math.abs(yes - no) <= Math.max(2, Math.ceil(total * 0.2))`. (`total`이 0이면 통과한다. 20문항이면 12 : 8까지, 5문항이면 3 : 2까지 허용된다.)
     어긴 경우 메시지에 `yes`·`no` 수를 담는다.
- 함수는 이 테스트 파일 안에 둔다. 앱 코드가 쓰지 않는 검사이기 때문이다(`duplicates`와 같은 자리).

### 2. 테스트(먼저) — 같은 파일에 `describe('예/아니요 문항')`

- **검사가 위반을 잡는다**: 픽스처 문항으로 — 물음표 없는 문제문, 「항상」이 든 문제문, 「절대」가 든 문제문, 예 5 : 아니요 1 — 각각 해당 문제가 보고된다.
  예 3 : 아니요 2이고 규칙을 지킨 픽스처는 빈 배열이다. 4지선다 픽스처는 문제문이 물음표로 끝나지 않고 「항상」이 들어 있어도 빈 배열이다.
- **모든 과목이 지킨다**: `subjects`의 과목마다(`it.each` 등, 테스트 이름에 과목 id) `yesNoProblems(subject.questions)`가 빈 배열이다.
  비율은 **과목 단위**로 잰다 — 주제 단위로 쪼개지 않는다.

픽스처를 먼저 써서 검사 함수가 없을 때 실패하는 것을 확인한 뒤 함수를 쓴다.

## 금지사항

- **4지선다 문항에 이 규칙을 걸지 마라.** 이유: 세 규칙은 예/아니요의 답이 새는 길을 막는 것이다. 4지선다에서는 「절대」가 답을 흘리지 않는다 —
  AWS `q242`(「계정이 절대 해서는 안 되는 행동을 제한하는 정책은 무엇인가?」)는 「절대」가 문제의 내용이다. 비율 규칙은 4지선다에 뜻이 없다.
- **과목마다 허용 오차를 다르게 두거나 예외 목록을 만들지 마라.** 이유: 불변식은 모든 과목에 같은 식으로 건다(ADR-053의 불변식과 같은 방식). 걸리면 문항을 고친다.
- **검사 함수를 `src/lib/`에 두지 마라.** 이유: 앱 런타임이 쓰지 않는다. `src/lib/`는 화면이 쓰는 규칙을 모아 두는 곳이다.
- AWS 데이터와 앱 코드를 고치지 마라. 이유: 이 step은 불변식 테스트만 더한다.
- 기존 테스트를 깨뜨리지 마라.
