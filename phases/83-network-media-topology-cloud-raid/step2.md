# Step 2: coax-optical-fiber

## 배경

phase 83은 네트워크 과목의 `transmission-media`·`network-topology`·`cloud-sdn`·`raid-storage`를 만든다. 전체 계획·결정·공통 규칙은 `phases/83-network-media-topology-cloud-raid/guide.md`에 있다.
**이 step은 `transmission-media`의 개념 둘(3 동축 케이블, 4 광케이블)의 글·문항·도식을 함께 만든다.** 둘 다 `transmission-media`에 딸린 개념이다.

기출은 광케이블을 가장 자주 묻는다 — 코어와 굴절률이 다른 클래딩([기출 2024-05-19 #48]·[기출 2025-08-24 #48]·[기출 2026-08-02 #50]), 손실이 적고 전자기 간섭을 받지 않는다([기출 2024-08-25 #46]),
대역폭이 넓다([기출 2024-11-03 #50]), 끊기면 따로 장비 없이 이을 수 없다·두 모드·보안과 잡음([기출 2024-02-25 #50]), 지문 누락 둘([기출 2025-02-23 #23]·[기출 2026-05-17 #23]). 처리는 step 0 결과대로.

### 3. 도식

#### 3-1. `coaxial-cable` — `CoaxLayersDiagram`, JSON 키 `coax-layers`

- 물음형 제목 예: `동축 케이블은 안에서 밖으로 무엇이 감싸고 있을까?`
- 그릴 것: 케이블의 가운데에서 바깥으로 한 방향으로 놓은 칸 노드 넷 — 「중심 도체」·「절연체」·「바깥 도체」·「피복」(본문의 말 — 원이나 단면 그림으로 그리지 않는다, guide.md 「도식」). 바깥에 「바깥 전기 잡음」 노드.
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `signal` | 신호가 지나는 곳 | 중심 도체·절연체 | 신호는 가운데 도체를 따라 간다(본문의 말대로) |
  | `shield` | 바깥 잡음 막기 | 바깥 도체·바깥 전기 잡음과 그 사이 경로 | 바깥 도체가 바깥 잡음이 안으로 드는 것을 막는다 |

- 요점 테스트: 칸 노드 넷이 중심 도체 → 절연체 → 바깥 도체 → 피복의 차례로 한 방향에 놓인다(좌표로). `shield`에서 「바깥 전기 잡음」에서 오는 경로의 끝이 바깥 도체 노드다.

#### 3-2. `optical-fiber` — `FiberCoreCladdingDiagram`, JSON 키 `fiber-core-cladding`

- 물음형 제목 예: `빛은 광섬유의 어디를 지나 나아갈까?`
- 그릴 것: 광섬유 둘을 위·아래로 — 위는 싱글 모드, 아래는 멀티 모드. 각각 「클래딩」 그룹 박스 둘 사이에 「코어」 그룹 박스(멀티 모드의 코어 박스가 더 굵다 — 굵기의 실제 값은 본문의 값이 있을 때만 곁말로), 왼쪽 「빛을 보내는 쪽」·오른쪽 「받는 쪽」 노드, 코어 박스 안을 지나는 가로 경로(싱글 모드는 하나, 멀티 모드는 둘 이상 — 본문이 말하는 「빛이 지나는 길(모드)」의 뜻대로). 경로는 직교로만 — 반사를 사선·곡선으로 그리지 않는다.
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `single` | 싱글 모드 | 위 광섬유의 양 끝과 경로 하나 | 가는 코어로 빛이 지나는 길이 하나라 먼 거리에 쓴다(본문대로) |
  | `multi` | 멀티 모드 | 아래 광섬유의 양 끝과 경로 여럿 | 굵은 코어로 빛이 여러 길로 나아간다(본문대로) |

- 요점 테스트: `single`의 보이는 경로가 하나이고 싱글 모드 「코어」 그룹 박스 안에 있다. `multi`의 보이는 경로가 둘 이상이고 모두 멀티 모드 「코어」 그룹 박스 안에 있으며 「클래딩」 박스 안으로 들어가지 않는다.

위 도식 설계는 출발점이다. 본문(step 0 결과)과 맞지 않거나 280 폭에 들지 않으면 바꾸되, 바꾼 것과 이유를 summary에 적는다.
