# Step 5: coding-multiplexing

## 배경

phase 83은 네트워크 과목의 `transmission-media`·`network-topology`·`cloud-sdn`·`raid-storage`를 만든다. 전체 계획·결정·공통 규칙은 `phases/83-network-media-topology-cloud-raid/guide.md`에 있다.
**이 step은 `transmission-media`의 개념 둘(7 채널 부호화, 8 다중화)의 글·문항·도식을 함께 만든다.** 둘 다 부모가 없는 개념이고, 8은 뒤 step의 `tdm`·`wdm`의 부모다.

기출은 오류를 찾고 고칠 비트를 더하는 채널 부호화의 예로 컨볼루션 부호를 고르게 하고([기출 2024-02-25 #26] — 오답 ADPCM·ADM·PCM), 여러 신호를 회선 하나로 보내고 받는 쪽에서 나누는 것이 다중화임을 묻는다([기출 2025-08-24 #21] — 오답 MODEM·DSU·CODEC).

### 3. 도식

#### 3-1. `channel-coding` — `ChannelCodingFlowDiagram`, JSON 키 `channel-coding-flow`

- 물음형 제목 예: `오류를 찾으려고 보내는 쪽은 무엇을 더할까?`
- 그릴 것: 위에서 아래로 차례 — 「원래 정보」 → 「원천 부호화」 → 「데이터 비트」 → 「채널 부호화」 → 「데이터 비트 + 여분 비트」 → 「매체」(곁말: 손상으로 비트가 바뀔 수 있다) → 「오류 검출·정정」 → 「데이터 비트」. 본문이 쓴 말만 쓴다.
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `source` | 원천 부호화 | 원래 정보·원천 부호화·데이터 비트 | 원래 정보를 디지털 비트로 바꾼다(본문대로) |
  | `channel` | 채널 부호화 | 채널 부호화부터 오류 검출·정정까지 | 여분 비트를 더해 보내고, 받는 쪽이 그것으로 오류를 찾거나 고친다 |

- 요점 테스트: 「데이터 비트 + 여분 비트」 노드가 `channel`에서 선명하고 `source`에서 흐리다. 두 시나리오의 선명한 노드 집합이 「데이터 비트」(첫 번째) 말고는 겹치지 않는다.

#### 3-2. `multiplexing` — `MuxDemuxDiagram`, JSON 키 `mux-demux`

- 물음형 제목 예: `여러 신호가 회선 하나를 어떻게 함께 쓸까?`
- 그릴 것: 입력 A·B·C(세로로) → 「다중화기」 → 「회선 하나」 → 「역다중화기」 → 출력 A·B·C. 회선 곁에 방식마다 다른 칸 노드 줄 셋 — FDM은 「주파수 구간 1·2·3」, TDM은 「슬롯 A·B·C」, WDM은 「파장 λ1·λ2·λ3」(셋은 서로 다른 자리 — 같은 자리에 겹쳐 두지 않는다).
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `fdm` | 주파수 분할 | 입출력·다중화기·역다중화기·회선과 주파수 구간 칸 | 신호마다 다른 주파수 구간을 준다 |
  | `tdm` | 시분할 | 같은 줄과 슬롯 칸 | 시간을 칸으로 나눠 차례로 준다 |
  | `wdm` | 파장 분할 | 같은 줄과 파장 칸 | 광섬유에 파장이 다른 빛을 함께 싣는다 |

- 요점 테스트: 세 시나리오에서 선명한 칸 노드 집합이 서로 겹치지 않는다. 입력 A에서 출력 A까지 보이는 경로가 세 시나리오 모두 다중화기 → 회선 → 역다중화기를 지난다.

위 도식 설계는 출발점이다. 본문(step 3 결과)과 맞지 않거나 280 폭에 들지 않으면 바꾸되, 바꾼 것과 이유를 summary에 적는다.
