# Step 19: raid1-raid5

## 배경

phase 83은 네트워크 과목의 `transmission-media`·`network-topology`·`cloud-sdn`·`raid-storage`를 만든다. 전체 계획·결정·공통 규칙은 `phases/83-network-media-topology-cloud-raid/guide.md`에 있다.
**이 step은 `raid-storage`의 개념 둘(3 RAID 1, 4 RAID 5)의 글·문항·도식을 함께 만든다.** 둘 다 `raid`에 딸린 개념이다.

기출은 미러링이라 부르는 레벨이 RAID 1임을 묻고([기출 2024-02-25 #46]·[기출 2026-05-17 #46] — 오답 RAID 0·3·5, 「최고의 성능」의 처리는 step 17 결과대로), 회전 패리티로 병목을 줄이는 레벨이 RAID 5임을 묻는다([기출 2025-08-24 #46] — 오답 RAID 2·3·4).

## 읽어야 할 파일

- guide.md 「개념을 넣는 step의 공통 — 읽어야 할 파일」 전부. 그에 더해:
- `phases/83-network-media-topology-cloud-raid/index.json`의 step 17 `summary`(RAID 1·4·5의 뜻·최소 수·용량·견디는 고장, 패리티의 원리와 놓이는 차례, 기출 판정, E 번호)와 step 18 `summary`(정한 단위 표기)
- `src/data/network/topics.json` — **`raid-storage`의 앞 개념 둘**(특히 `raid`의 세 방법 한 줄 — 뜻을 맞춘다)
- 도식 선례: `RaidArrayDiagram`·`RaidStripingDiagram`(이 phase)과 그 테스트

### 3. 도식

#### 3-1. `raid-1` — `RaidMirroringDiagram`, JSON 키 `raid-mirroring`

- 물음형 제목 예: `RAID 1은 디스크 하나가 고장 나도 어떻게 데이터를 지킬까?`
- 그릴 것: 위에 「쓰는 데이터」 노드, 아래에 `DISK0`·`DISK1` 그룹 박스와 그 안의 같은 조각 칸(A1·A2·A3 — 디스크마다 따로의 id), 「쓰는 데이터」에서 두 디스크로 가는 경로, 읽기 시나리오용으로 디스크에서 「읽는 쪽」 노드로 가는 경로.
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `write` | 똑같이 쓰기 | 쓰는 데이터·두 디스크의 칸과 두 경로 | 같은 데이터를 두 디스크에 똑같이 쓴다 |
  | `fail` | 디스크 하나의 고장 | `DISK1`의 칸·읽는 쪽과 `DISK1` → 읽는 쪽 경로(`DISK0`의 칸은 흐림) | `DISK0`이 고장 나도 `DISK1`의 같은 데이터로 계속 읽는다 |

- 요점 테스트: `write`에서 「쓰는 데이터」에서 나간 보이는 경로가 둘이고 끝이 서로 다른 디스크 그룹 안이다. `fail`에서 보이는 읽기 경로의 시작이 `DISK1` 그룹 안의 노드이고 `DISK0`의 칸이 모두 opacity 0.25다.

#### 3-2. `raid-5` — `RaidParityRotationDiagram`, JSON 키 `raid-parity-rotation`

- 물음형 제목 예: `RAID 5는 패리티를 어디에 두고, 고장 난 조각을 어떻게 되살릴까?`
- 그릴 것: 디스크 넷(`DISK0`~`DISK3` 그룹 박스 — 280 폭에서 두 줄로 둘씩, 440 폭에서 한 줄에 넷), 디스크마다 칸 넷(줄 넷 — 줄마다 데이터 칸 셋과 패리티 칸 하나, 패리티 P1~P4가 줄마다 다른 디스크에 — 놓이는 차례는 본문대로). 다시 계산 시나리오용으로 「다시 계산한 조각」 노드(디스크 밖 다른 자리)와, 같은 줄의 남은 칸에서 그 노드로 가는 경로.
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `layout` | 패리티 돌려 놓기 | 칸 열여섯 | 줄마다 패리티가 다른 디스크에 놓여 패리티 쓰기가 한 디스크에 몰리지 않는다 |
  | `rebuild` | 조각 다시 계산 | 고장 난 디스크(본문 예의 것)의 칸을 뺀 첫 줄의 칸과 「다시 계산한 조각」, 그 경로 | 남은 조각과 패리티로 잃은 조각을 다시 계산한다(본문대로) |

- 요점 테스트: 패리티 칸 넷이 서로 다른 디스크 그룹 안에 있다(좌표로). `rebuild`에서 「다시 계산한 조각」으로 들어가는 보이는 경로의 시작 칸이 모두 같은 줄에 있고, 고장 난 디스크 그룹 안의 칸에서 시작하는 경로가 없다.

위 도식 설계는 출발점이다. 본문(step 17 결과)과 맞지 않거나 280 폭에 들지 않으면 바꾸되, 바꾼 것과 이유를 summary에 적는다. 칸 열여섯이 280 폭에서 노드 폭 규칙(라벨 + 12)을 지키지 못하면 칸 라벨을 줄이지 말고 배치를 바꾼다.
