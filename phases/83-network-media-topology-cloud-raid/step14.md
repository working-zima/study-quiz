# Step 14: serverless-datacenter

## 배경

phase 83은 네트워크 과목의 `transmission-media`·`network-topology`·`cloud-sdn`·`raid-storage`를 만든다. 전체 계획·결정·공통 규칙은 `phases/83-network-media-topology-cloud-raid/guide.md`에 있다.
**이 step은 `cloud-sdn`의 개념 둘(3 서버리스 컴퓨팅, 4 인터넷 데이터 센터)의 글·문항·도식을 함께 만든다.** 3은 `cloud-computing`에 딸린 개념, 4는 부모가 없는 개념이다.

기출은 서버리스에서 「사용자가 서버 인스턴스 준비와 OS 패치를 직접 한다」가 틀린 말임을 묻고([기출 2025-11-02 #27]), 지문이 빠진 문항에서 IDC를 고르게 한다([기출 2024-02-25 #18] — 오답 IPS·IDS·IOS).

## 읽어야 할 파일

- guide.md 「개념을 넣는 step의 공통 — 읽어야 할 파일」 전부. 그에 더해:

- `src/data/network/topics.json` — **`cloud-sdn`의 앞 개념 둘**(특히 `cloud-computing`의 서비스 모델 문단 — 뜻을 맞춘다), `windows-hyperv.hyper-v`(운영 체제 — 뜻을 맞춘다)
- 도식 선례: `ZigbeeStackDiagram`·`OsiStackDiagram`(쌓은 칸과 맡는 범위), `CloudTraitsDiagram`(이 phase), `VirtualSwitchTypesDiagram`과 그 테스트

**step 12의 「사용자 확인」에 서버리스의 근거를 찾지 못했다고 적혀 있으면** 이 step은 `serverless` 개념·문항·도식을 만들지 말고 `data-center`만 만든 뒤 `"status": "blocked"`, `"blocked_reason"`에 그 사유를 적고 멈춘다 — 근거 없는 개념을 쓰지 않고, 개념 순서를 바꾸지 않기 위해서다.

### 3. 도식

#### 3-1. `serverless` — `ServerlessDutiesDiagram`, JSON 키 `serverless-duties`

- 물음형 제목 예: `서버리스에서는 사용자가 어디까지 맡을까?`
- 그릴 것: 아래에서 위로 쌓은 칸 노드 넷 — 「서버(하드웨어)」·「운영 체제」·「실행 환경」·「코드」(본문의 말 — 본문이 셋으로 나눴으면 셋). 옆에 「사용자가 맡는 것」·「제공자가 맡는 것」 노드 둘과 칸으로 가는 경로(시나리오마다 다른 경로 — 같은 칸에 두 경로가 겹치지 않게 경로 id를 따로).
- 시나리오:

  | id | label | 선명한 것 | 곁말·캡션이 말할 것 |
  |---|---|---|---|
  | `iaas` | IaaS | 사용자 노드와 운영 체제·실행 환경·코드, 그 경로 | IaaS에서는 운영 체제부터 위를 사용자가 맡는다(본문대로) |
  | `serverless` | 서버리스 | 사용자 노드와 코드, 제공자 노드와 아래 칸 셋, 그 경로 | 사용자는 코드만, 나머지는 제공자가 맡는다 |

- 요점 테스트: 「사용자가 맡는 것」에서 나간 보이는 경로가 닿는 칸 집합이 `iaas`에서는 셋, `serverless`에서는 「코드」 하나다. 「서버(하드웨어)」 칸은 두 시나리오 모두 사용자 경로가 닿지 않는다.

#### 3-2. `data-center` — `DataCenterServicesDiagram`, JSON 키 `data-center-services`

- 물음형 제목 예: `데이터 센터는 서버에게 무엇을 내줄까?`
- 그릴 것: 「인터넷 데이터 센터」 그룹 박스 안에 `WEB01`과 설비 노드(전원·냉방·인터넷 회선·보안 — 본문에 쓴 것만), 설비에서 `WEB01`로 가는 경로, 그룹 박스 바깥에 `example.com`(서버를 맡긴 쪽)과 「인터넷」 노드.
- 정지 그림(시나리오 없음)으로 해도 된다 — 본문이 맡기기·빌리기 둘을 가르면 시나리오 `colocation`·`hosting`을 둔다(서버의 주인이 누구인지를 곁말로).
- 요점 테스트: 정지 그림이면 — 설비 노드에서 나간 경로가 모두 `WEB01`에 닿고, `WEB01`과 설비 노드가 모두 「인터넷 데이터 센터」 그룹 박스 안에 있다. 시나리오가 있으면 두 시나리오의 곁말이 다르다.

위 도식 설계는 출발점이다. 본문(step 12 결과)과 맞지 않거나 280 폭에 들지 않으면 바꾸되, 바꾼 것과 이유를 summary에 적는다.
