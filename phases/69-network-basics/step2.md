# Step 2: interview-facts

## 배경

앱에 두 번째 과목 **네트워크**를 더하는 phase 69의 셋째 step이다. 사용자 결정(2026-10-26, 다시 묻지 마라): 강의 자료 압축 파일에 든 「기술면접 TOP 50」 가운데
**네트워크 21~40번**(문장으로 쓴 답이 있다)을 **사실 출처로도 쓴다.** 다만 틀린 답이 있다. 틀린 것은 표준 문서(IETF RFC, IANA, IEEE 802, ITU-T X.200, MDN)로 고치고
**수정 이력을 남긴다.** 설계 때 찾은 예가 22번의 「UDP는 손상된 데이터를 감지하지 않는다」다 — UDP에는 손상을 검출하는 체크섬이 있다.
사용자는 면접 자료를 「무엇을 강조할지 고르는 기준으로만」 쓰자는 권고 대신 이 방식을 골랐다.

앞 step이 만든 것:

- step 0: `docs/source/network/raw/interview.md` — 면접 두 PDF의 글자(gitignore). `docs/source/network/CLAUDE.md` — 네트워크 원본 규칙.
- step 1: `docs/source/network/lecture-outline.md` — 강의 32강 정리, **주제 지도(22개)**, 강의 수정 이력 `L1…`. `docs/source/network/standards.md` — 표준 문서 사실과 URL.

**이 step은 면접 21~40번에서 사실을 뽑아 `docs/source/network/interview-facts.md`를 쓰고, 고친 것의 근거를 `standards.md`에 더한다.**

## 읽어야 할 파일

- `docs/source/network/CLAUDE.md` — **이 규칙을 따른다**
- `docs/source/network/raw/interview.md` — 전부
- `docs/source/network/lecture-outline.md` — 주제 지도와 강의 수정 이력(같은 사실을 강의도 다루면 번호를 서로 가리킨다)
- `docs/source/network/standards.md` — 이미 있는 절은 다시 만들지 말고 「쓰인 곳」만 더한다
- `docs/ADR.md`의 **ADR-009**, **ADR-021**(덤프 해설의 사실 오류를 고치고 「원본 수정 이력」에 남긴 선례), **ADR-054**
- `docs/source/exam-gaps.md`의 「원본 수정 이력」 절 — 수정 이력 형식의 선례(AWS)

## 작업

### 1. `docs/source/network/interview-facts.md`

머리말 몇 줄 — 무엇인지, 출처(강의 자료의 기술면접 TOP 50 네트워크 21~40번), 원문은 `raw/interview.md`(gitignore), 문장은 직접 쓴다(ADR-009),
틀린 답은 표준으로 고쳤고 그 기록이 아래 「수정 이력」이라는 것.

문항마다 절 하나 — `## Q22 TCP와 UDP의 차이 → tcp-udp`. 그 아래:

- **묻는 것** — 한 줄, 직접 쓴 말.
- **사실** — 답이 담은 사실을 글머리 기호로, 직접 쓴 말로. 틀린 사실은 고친 내용으로 적고 끝에 `(수정 I3)`처럼 수정 이력 번호를 붙인다.
- **주제** — `lecture-outline.md` 주제 지도의 주제 id. 둘 이상이면 모두. 강의 범위 밖이면 「강의 범위 밖」과 이유.
- **문항 형식 메모**(있을 때만) — 흔한 오해를 겨냥하는 사실이면 「예/아니요 감」이라고 적는다. ADR-054 기준 「잘못 알기 쉽다 → 예/아니요」. 수정 이력이 붙은 사실은 대개 그렇다.

### 2. 수정 이력

파일 끝 절. 항목마다 번호(`I1`, `I2`…), 면접 번호, 답이 말한 것의 요지(직접 쓴 말), 표준이 말하는 것(직접 쓴 말), 근거(문서와 절, URL), 처리(고쳐 쓴다 / 쓰지 않는다 /
한정해 쓴다), 같은 문제를 다룬 강의 수정 이력 번호(있으면). **표준 문서를 실제로 열어(WebFetch) 확인한 것만** 적는다.

설계 때 찾은 후보다. **하나씩 확인하고**, 맞으면 기록하고, 표준이 면접 답 편이면 「확인 결과 답이 맞다」로 남긴다. 읽다가 다른 곳을 찾으면 더한다.

| 후보 | 문항 | 답이 말한 것 | 확인할 것 |
|---|---|---|---|
| 1 | Q21 | 데이터 링크 계층이 오류를 「검출하고 수정」 | 이더넷은 FCS로 오류를 검출하면 프레임을 버리고 고치지 않는지 — IEEE 802.3. OSI 계층의 정의는 ITU-T X.200 |
| 2 | Q22 | TCP가 손상된 데이터를 「감지하고 수정」 | 체크섬으로 검출하고 재전송으로 복구하는 것인지 — RFC 9293 |
| 3 | Q22 | UDP는 손상된 데이터를 「감지하지 않는다」 | 체크섬으로 검출한다. IPv4에서는 선택, IPv6에서는 필수. 복구는 하지 않는다 — RFC 768, RFC 8200 |
| 4 | Q22 | UDP는 「대용량 데이터 전송」에 적합 | 근거가 있는지. 없으면 쓰지 않는다. UDP를 쓰는 예는 강의 정리(`lecture-outline.md`)의 것을 쓴다 |
| 5 | Q25 | 서브넷 마스크는 「2진수로 표시」 | 보통 점으로 구분한 10진수나 접두사 길이(`/24`)로 적고, 비트로 보면 1이 네트워크·0이 호스트인지 — RFC 4632, RFC 950 |
| 6 | Q28 | 리다이렉션이 「캐시된 데이터를 사용 가능한지」도 알린다(304) | 304는 3xx 범위지만 다른 URI로 보내지 않는 응답인지 — RFC 9110 |
| 7 | Q29 | 4xx는 다시 보내도 성공하지 않을 가능성이 높고, 5xx는 다시 보내면 결과가 달라질 수 있다 | 표준이 정한 것은 오류의 원인 쪽(클라이언트·서버)인지, 재시도 결과에 대한 주장은 일반화인지, 408·429·`Retry-After` 같은 예외 — RFC 9110, RFC 6585 |
| 8 | Q37 | IPv4 주소는 약 43억 개 | 2^32 = 4,294,967,296 — RFC 791. 맞으면 「답이 맞다」 |

Q34(트래픽이 몰릴 때 웹 서버 구성: 로드 밸런서, 오토 스케일링, 정적 콘텐츠 캐싱, DB 이중화)는 강의의 「트래픽을 분산한다」(Ch1-4)와 웹 서버 주제에 닿지만
나머지는 강의 범위 밖이다. 사실은 적되 주제 칸에 어디까지 쓸 수 있는지 적는다.

### 3. `docs/source/network/standards.md`

수정 이력이 쓰는 표준 사실을 step 1과 같은 형식으로 더한다. 이미 있는 문서 절은 새로 만들지 말고 사실 줄과 「쓰인 곳」(`면접 수정 이력 I3` 등)만 더한다.

## Acceptance Criteria

```bash
grep -c "^## Q" docs/source/network/interview-facts.md      # 20 (Q21~Q40)
grep -nE "I[0-9]+" docs/source/network/interview-facts.md | head -40
grep -c "^## " docs/source/network/standards.md
git status --porcelain
```

## 검증 절차

1. AC를 실행한다. 문항 절이 20개여야 하고 수정 이력 번호가 보여야 한다.
2. **전사 검사**: `interview-facts.md`의 각 줄을 `raw/interview.md`와 대조해, 공백·문장부호를 지우고 **20자 이상** 연속으로 같은 구간이 있는지 확인한다
   (일회성 스크립트는 저장소 밖 임시 폴더에 두고 끝나면 지운다). 면접 답은 완성된 문장이라 강의 슬라이드보다 옮기기 쉬우므로 기준을 낮춰 본다.
   한글이 없는 구간은 넘긴다. 걸리면 직접 쓴 말로 고친다.
3. 수정 이력의 근거 URL과 절 번호를 다시 연다. 열 수 없었던 것은 「확인 못 함」, 처리는 「쓰지 않는다」.
4. 문항마다 「주제」 칸의 id가 `lecture-outline.md` 주제 지도에 있는지 확인한다.
5. `git status`로 바뀐 파일이 `docs/source/network/interview-facts.md`, `docs/source/network/standards.md`와 phase 메타데이터뿐인지 확인한다.
6. `phases/69-network-basics/index.json`의 step 2를 갱신한다.
   - 성공 → `"summary"`에 문항 절 수, 수정 이력 항목 수와 번호별 한 줄 요지(후보 1~8 각각의 결과 포함, 새로 더한 것 표시), 주제별로 쓰이는 면접 번호, 「예/아니요 감」 표시 수, `standards.md`에 더한 문서를 적는다.
   - WebFetch를 전혀 쓸 수 없으면 → `"status": "blocked"`, `"blocked_reason"`에 사유를 적고 멈춘다.

## 금지사항

- **면접 답 문장을 그대로 옮기지 마라.** 이유: 외부 자료다(ADR-009). 답이 완성된 문장이라 한 문장만 옮겨도 원문이 된다.
- **틀린 답을 고치지 않은 채 「사실」에 두지 마라.** 이유: 이 문서는 뒤 step이 개념 본문과 문항을 쓰는 근거다. 틀린 사실이 들어가면 그대로 가르친다.
- **표준을 확인하지 않고 「고쳤다」고 적지 마라.** 이유: 수정의 근거가 URL로 남아야 다음 사람이 다시 확인할 수 있다.
- **`lecture-outline.md`의 주제 지도와 강의 정리를 고치지 마라.** 이유: step 1의 산출물이고 주제 지도는 사용자가 승인한 구성이다. 강의 수정 이력에 번호를 더해 서로 가리키는 것만 허용한다.
- `src/`·`docs/*.md`를 고치지 마라. 이유: 이 step은 원본 문서만 만든다.
- 기존 테스트를 깨뜨리지 마라.
