# Step 0: addressing-sources

## 배경

phase 74는 네트워크 과목의 `ip-addressing`(IP 주소와 서브넷 마스크)·`ip-address-types`(공인·사설 IP, NAT, DHCP)·`routing`(라우팅)을 만든다. 전체 계획과 결정은 `phases/74-network-addressing-routing/guide.md`에 있다.
step 1~4가 `ip-addressing`의 개념 8개를 쓰기 전에, **이 step은 그 개념들이 쓸 사실 가운데 강의 밖이거나 강의가 틀렸을 수 있는 것을 표준 문서로 확인하고 출처 문서에 남긴다.**
데이터·코드는 고치지 않는다. 뒤 step은 이 step이 남긴 기록과 summary를 보고 무엇을 쓰고 무엇을 쓰지 않을지 정한다.

`ip-addressing`은 기출 19문항 가운데 11문항이 서브넷 계산이고 4문항이 클래스 판별이다. 강의는 클래스 A·B·C, 네트워크·브로드캐스트 주소, 서브넷 마스크와 AND, CIDR 표기까지 보여 주고
서브네팅 계산은 계산기 화면 하나뿐이다. 그래서 서브네팅 규칙(서브넷 수·호스트 수)과 D·E 클래스는 **이 step이 확인한 것만** 뒤 step이 쓸 수 있다.

## 작업

### 1. 확인할 것 — 하나씩 허용한 출처를 실제로 열어 확인한다

볼 곳은 `rfc-editor.org`(RFC 본문 — 텍스트판을 받아 절을 직접 읽는다)와 `iana.org`(레지스트리)가 중심이다. RFC는 지금 유효한 것을 쓰고, 폐기되거나 역사적(Historic)이 된 RFC는 역사 기록으로만 쓰고 그렇다고 밝힌다(`standards.md` 규칙).
RFC의 상태(Standard·Informational·Historic·폐기)는 rfc-editor의 문서 정보로 확인한다. 위키백과·블로그·업체 학습 페이지는 쓰지 않는다.

| # | 개념 | 확인할 것 | 볼 곳(예) |
|---|---|---|---|
| a | `network-host` | IPv4 주소가 네트워크 번호와 그 네트워크 안의 주소(호스트 번호)로 이뤄진다는 것. 같은 네트워크의 호스트는 네트워크 번호가 같다. 경계가 주소 모양만으로 정해지지 않는다는 것(클래스·서브넷 마스크·접두사 길이가 정한다) | RFC 791 §2.3(이미 있는 항목에 더한다), RFC 950 §2.1, RFC 1122 §3.2.1.3, RFC 4632 §3.1 |
| b | `network-broadcast-address` | 호스트 부분이 모두 0인 주소와 모두 1인 주소의 뜻과 이름(네트워크 자체 / 그 네트워크로의 브로드캐스트 — directed broadcast), 둘을 호스트에 주지 않는다는 근거. 그래서 쓸 수 있는 호스트 수가 2^h − 2라는 것을 표준 문장으로 댈 수 있는지(없으면 위 두 사실에서 계산으로 보인다고 적는다). 점대점 링크의 `/31` 예외는 이름과 절만 | RFC 1122 §3.2.1.3, RFC 919 §7(이미 있는 항목), RFC 922, RFC 950 §2.1, RFC 1812 §4.2.2.11·§5.3.5, RFC 3021 |
| c | `address-classes` | A·B·C 클래스의 맨 앞 비트와 네트워크 부분의 크기(RFC 791 §2.3 — L6과 함께 이미 있다), 첫 옥텟의 10진수 범위. **D 클래스**(맨 앞 `1110`, 멀티캐스트 — 네트워크·호스트로 나누지 않는다)와 **E 클래스**(`1111`, 예약)의 근거. 첫 옥텟 0과 127이 따로 쓰인다는 것(이 네트워크·루프백 — 자세히는 step 5). 클래스로 경계를 정하는 방식이 지금은 쓰이지 않는다는 근거 | RFC 791 §2.3, RFC 1112 §4, RFC 5771(멀티캐스트 주소), IANA 「IPv4 Multicast Address Space Registry」, RFC 1122 §3.2.1.3, RFC 4632 §1·§2 |
| d | `cidr` | CIDR가 무엇이고 왜 나왔는지(옛 B 클래스 주소의 고갈과 라우팅 표의 증가 — 문서가 그렇게 말하는지), 접두사 길이 표기(이미 있다), 클래스 경계가 아니라 아무 비트에나 경계를 둔다는 것. CIDR가 「Classless Inter-Domain Routing」의 줄임이라는 것 | RFC 4632 §1·§2·§3.1(이미 있는 항목에 더한다), RFC 1519(폐기 — 역사 기록) |
| e | `subnet-mask` | 마스크의 뜻·표기(RFC 950·RFC 4632 — 이미 있다), 클래스마다의 기본 마스크(A `255.0.0.0`·B `255.255.0.0`·C `255.255.255.0`)를 표준으로 댈 수 있는지. **호스트가 마스크로 목적지가 같은 네트워크(직접 이어진 네트워크)에 있는지 가린다**는 것 — 같으면 바로 보내고 다르면 라우터로 보낸다 | RFC 950 §2.1·§2.2·Appendix I, RFC 1122 §3.3.1.1, RFC 4632 §3.1·§5.1 |
| f | `network-address-calc` | 주소와 마스크의 비트 AND로 네트워크(와 서브넷) 번호를 얻는다는 근거 | RFC 950 Appendix I(또는 해당 절), RFC 1122 §3.3.1.1 |
| g | `subnetting` | 서브넷 필드를 호스트 필드의 앞쪽 비트에서 가져온다는 것, 서브넷 수는 그 비트 수로 정해진다는 것. **서브넷 번호가 모두 0인 서브넷과 모두 1인 서브넷**을 쓰지 말라던 옛 권고(RFC 950)와, 그것을 지금은 쓴다는 근거(있는지, 어느 문서·절인지, 그 문서의 상태) | RFC 950 §2.1, RFC 1812 §4.2.2.11·§5.3.5, RFC 1878(상태 확인 — Historic이면 역사 기록), RFC 4632 |
| h | `subnet-sizing` | 접두사 길이별 주소 수와 호스트 수(2^(32−n), 2^(32−n) − 2)를 표준 문장으로 댈 수 있는지 — 없으면 a·b·g의 사실에서 계산으로 보인다고 적는다. 기출 [2025-05-25 #4]가 C 클래스 `/26`의 서브넷 수를 4로 보는 것이 g의 지금 규칙과 맞는지 | RFC 4632 §3.1, RFC 1878, g의 결과 |
| i | 예시 값 | guide.md 「예시 값」의 문서용 대역(`standards.md`에 이미 있다)으로 이 주제의 예를 모두 만들 수 있는지. 서브네팅 예(`192.0.2.0/24`를 `/26` 넷으로), AND 예(`192.0.2.130` AND `255.255.255.192` = `192.0.2.128`)를 직접 계산해 맞는지 | RFC 5737 §3(이미 있다) |

빠진 것을 읽다가 찾으면 더한다. 강의 Ch3-5 p161–p179에서 표준과 다르거나 오해를 부르게 줄여 말한 곳이 더 있으면 같은 방법으로 확인한다.
예를 들어 p171 그림의 네트워크 주소·브로드캐스트 주소, p172의 「클래스리스가 오늘날 주로 쓰는 방식」, p174의 「서브넷 마스크는 비트열」(I5와 겹치는지), p178–p179 계산기 결과의 수가 표준·계산과 맞는지 본다.
p164(MAC 주소 비교)는 L2·L29에 이미 걸려 있다 — 다시 확인하지 않는다.

### 2. `docs/source/network/standards.md` — 확인한 사실을 더한다

- 기존 항목의 형식을 따른다: `## (phase 74) <문서 이름> — <절 제목>`, URL 한 줄, 직접 쓴 사실 한 줄씩 끝에 `— §절 번호`, 「쓰인 곳」.
  **같은 RFC의 기존 항목(RFC 791·RFC 950·RFC 4632·RFC 1122·RFC 919·RFC 1112·RFC 1812 등)이 있으면 새 항목을 만들지 말고 그 항목에 「(phase 74)」를 붙인 줄로 더한다.**
  머리말의 「(phase 73)」 설명 다음 줄에 「(phase 74)」가 무엇인지(이 phase의 주소·NAT·DHCP·라우팅 사실, 확인한 날) 한 줄을 더한다.
- 폐기되거나 역사적이 된 RFC를 쓰면 항목 제목에 `[폐기, RFC xxxx로 대체 — 역사 기록으로만 쓴다]`(또는 `[Historic — 역사 기록으로만 쓴다]`)를 붙인다(RFC 1631 항목이 본보기).
- 「쓰인 곳」에는 아직 개념 id가 없으므로 **쓰일 개념 id**(`ip-addressing.subnetting` 등)와 수정 이력·exam-notes 번호를 적는다.

### 3. `docs/source/network/lecture-outline.md` — 수정 이력

- 확인 결과 강의가 표준과 다르거나 오해를 부르게 줄여 말했으면 `### L36 — …`부터 번호를 이어 「강의 수정 이력」 끝에 더한다. 형식은 L33~L35와 같다 —
  강의(직접 쓴 말)·표준(직접 쓴 말)·근거(문서와 절, URL)·처리(**고쳐 쓴다 / 한정해 쓴다 / 쓰지 않는다**).
  제목 끝에는 `[phase 74에서 찾음]`을 붙인다. 「설계 때 받은 후보」 표는 phase 69의 기록이라 고치지 않는다.
- 「강의 수정 이력」 머리의 「phase 73 step 1에서 …」 문단 뒤에 「phase 74 step 0에서 …」 문단을 더해 무엇을 더했는지(없으면 「Ch3-5에서 새로 찾은 것 없음」)와 표준과 어긋나지 않은 강의 사실을 적는다.
- 「강의별 정리」의 Ch3-5 절에서 해당 줄 끝에 `⚠ L번호`를 단다(L6처럼). 줄의 내용은 강의가 말한 것 그대로 둔다.
- 확인 결과 강의가 맞으면 수정 이력을 만들지 않고 summary에 「확인 결과 강의가 맞다」로 적는다.

### 4. `docs/source/network/exam-notes.md` — 시험의 답이 표준과 다르거나 표준에 없는 곳

이 주제의 기출 문항(`data.txt`의 `ip-addressing` 줄)이 정답으로 보는 것이 허용한 출처에 없거나 다르면 `## E15 — …`부터 번호를 이어 더한다(E9~E14 형식 — 시험·표준·처리·쓰인 곳).
표준에 있으면 항목을 만들지 않는다. E9 앞의 「E9~E14는 phase 73 …」 문단처럼 이 step이 더한 항목을 소개하는 문단을 새 항목 앞에 둔다(확인한 날 포함).

미리 본 후보 — 확인한 뒤 해당하면 항목으로 남긴다.

- **서브넷 수의 규칙**([기출 2025-05-25 #4]): 시험은 C 클래스 `/26`의 서브넷을 4개로 센다(지금 규칙). 지금 규칙의 근거가 표준에 있으면 항목을 만들지 않고 summary에 「본문은 2^k로 센다」를 적는다.
  근거가 옛 규칙(RFC 950)뿐이고 지금 규칙을 말하는 유효한 문서가 없으면, 처리를 「본문은 표준이 말한 것(옛 권고와 그것이 바뀌었다는 사실 중 확인된 것)을 쓰고, 「자격시험은 서브넷 번호가 모두 0·모두 1인 서브넷도 센다」를 덧붙인다」로 적는다.
- **기본 마스크**([기출 2024-02-25 #6], [기출 2025-05-25 #2], [기출 2026-08-02 #3]): 클래스마다 기본 마스크가 다르다는 것이 표준으로 확인되면 항목을 만들지 않는다.

### 5. summary — 뒤 step이 이것을 보고 쓴다

`ip-addressing`의 개념 8개마다 한 줄씩: **무엇을 쓸 수 있는지(출처와 함께), 무엇을 고쳐 쓰는지(L번호), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호)**.
위 표의 a~i마다 결과(확인함/강의가 맞음/못 찾음)와 근거 문서를 적는다. 못 찾은 것은 무엇을 어디서 찾아봤는지 적는다. 끝에 「사용자 확인」 칸을 둔다(없으면 「없음」).

## 금지사항

- **`src/`의 데이터·코드·테스트를 고치지 마라.** 이유: 이 step은 출처만 확인한다. 개념은 step 1~4가 쓴다.
- **확인하지 못한 사실을 standards.md·수정 이력에 적지 마라.** 이유: 뒤 step이 이 기록을 근거로 학습자에게 가르친다. 못 찾았으면 못 찾았다고 summary에 적는다.
- **허용한 출처 밖의 문서(위키백과·블로그·자격증 교재·업체 학습 페이지, 강의가 가리킨 온라인 서브넷 계산기)를 근거로 쓰지 마라.** 이유: ADR-059.
- **강의·기출·표준 문서의 문장을 옮기지 마라.** 이유: ADR-009·ADR-057.
- **`ip-address-types`·`routing`의 사실(사설 대역·예약 주소·루프백·NAT·DHCP·라우팅 테이블·라우팅 프로토콜)을 이 step에서 정리하지 마라.** 이유: step 5·11의 범위다. 읽다가 본 것은 summary에 메모만 한다.
  단 첫 옥텟 0·127이 따로 쓰인다는 것처럼 이 주제의 개념이 기대는 한 줄은 절 번호만 적어 둔다.
- **`docs/source/network/CLAUDE.md`·`topic-map.md`를 고치지 마라.** 이유: 이 step이 쓰는 출처는 모두 이미 허용한 곳(IETF RFC·IANA)이다.
