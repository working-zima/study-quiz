# Step 11: routing-sources

## 배경

phase 74는 네트워크 과목의 `ip-addressing`·`ip-address-types`·`routing`을 만든다. 전체 계획과 결정은 `phases/74-network-addressing-routing/guide.md`에 있다.
step 12~16이 `routing`의 개념 9개를 쓰기 전에, **이 step은 그 개념들이 쓸 사실 가운데 강의 밖이거나 강의가 틀렸을 수 있는 것을 표준 문서로 확인하고 출처 문서에 남긴다.**
데이터·코드는 고치지 않는다. 뒤 step은 이 step이 남긴 기록과 summary를 보고 무엇을 쓰고 무엇을 쓰지 않을지 정한다. `ip-addressing`·`ip-address-types`는 이미 끝났다.

`routing`은 기출 12문항 가운데 7문항이 강의에 없는 라우팅 프로토콜의 세부다 — RIP의 메트릭은 홉 수뿐, OSPF는 다익스트라·Hello·같은 비용 경로 여럿·판이 IP 판마다 다름, BGP는 경로 벡터·정책.
강의는 RIP·OSPF·BGP의 이름과 거리 벡터·링크 상태라는 말만 보여 주므로, 그 세부는 **이 step이 확인한 것만** 뒤 step이 쓸 수 있다.

### 1. 확인할 것 — 하나씩 허용한 출처를 실제로 열어 확인한다

볼 곳은 `rfc-editor.org`(RFC 본문 — 텍스트판을 받아 절을 직접 읽는다)와 `iana.org`가 중심이고, Linux·Windows 명령은 `man7.org`·`learn.microsoft.com`이다.
RFC는 지금 유효한 것을 쓰고, 폐기되거나 역사적이 된 RFC는 역사 기록으로만 쓰고 그렇다고 밝힌다. 위키백과·블로그·업체 학습 페이지는 쓰지 않는다. 시스코 문서는 VTP에만 허용했으므로 여기서 쓰지 않는다.

| b | `routing-table` | 라우팅 테이블의 칸 — 목적지, 마스크(접두사 길이), 다음 홉(게이트웨이), 내보낼 인터페이스, 메트릭 — 을 표준이 어떻게 말하는지. 메트릭이 경로의 비용이고 작을수록 좋다는 것. 호스트에도 라우팅 표가 있다는 것. 호스트에서 표를 보는 명령의 이름(Linux `ip route`·`route`, Windows `route print`·`netstat -r`)은 이름만 공식 문서로 | RFC 1812 §5.2.4·§5.2.4.1, RFC 1122 §3.3.1, man7.org `ip-route(8)`·`route(8)`, learn.microsoft.com `route` |

| e | `static-dynamic-routing` | 정적 경로(관리자가 넣는다)와 동적 경로(라우팅 프로토콜이 배운다)의 근거. 정적 경로는 망이 바뀌어도 스스로 바뀌지 않는다는 것. 기출 보기 「정적 라우팅은 라우터에 부하가 적어 메모리 관리에 유리하고 우선순위가 높다」를 표준이 말하는지 — 부하는 라우팅 프로토콜 메시지를 주고받지 않으므로라는 설명을 댈 수 있는지, 「우선순위」(같은 목적지에 정적·동적 경로가 함께 있을 때 어느 쪽을 쓰는가)를 표준이 정하는지 | RFC 1812 §7.1·§7.2·§5.2.4 |
| f | `as` | AS의 정의(하나의, 분명히 정해진 라우팅 정책을 가진 IP 접두사·라우터의 묶음), AS 번호를 IANA·RIR이 나눠 준다는 것, 문서용 AS 번호 대역(쓰지는 않는다 — 이름표만 쓴다). IGP·EGP라는 말의 근거(AS 안 / AS 사이의 라우팅 프로토콜). **「EGP」가 갈래 이름이면서 옛 프로토콜 하나(Exterior Gateway Protocol)의 이름이기도 하다**는 것 — 그 옛 프로토콜의 문서와 상태 | RFC 1930 §3·§4, RFC 4271 §1, RFC 1812 §7, RFC 904(옛 EGP — 상태 확인), RFC 5398(문서용 AS 번호), IANA 「Autonomous System (AS) Numbers」 |

RIP가 작은 네트워크용이라는 근거 | RFC 2453 §1·§3·§3.4·§3.8·§4, RFC 1058(RIPv1 — 상태 확인), RFC 2080(RIPng — 이름만) |
| h | `ospf` | 링크 상태 방식의 뜻(라우터마다 자기 링크 상태를 퍼뜨려 모두 같은 데이터베이스를 갖고, 저마다 최단 경로 나무를 계산한다), 계산에 다익스트라 알고리즘을 쓴다는 것, Hello 패킷으로 이웃을 찾고 살아 있는지 본다는 것, 메트릭이 비용(cost)이라는 것, **비용이 같은 경로 여럿을 함께 쓸 수 있다**(같은 비용 다중 경로)는 것, OSPF가 AS 안에서 쓰는 IGP라는 것, IPv4는 OSPFv2·IPv6는 OSPFv3라는 것. 영역(area)은 이름만 | RFC 2328 §1·§1.1·§2·§9.5·§10·§16.1·§16.8, RFC 5340 §1·§2 |
| i | `bgp` | BGP가 AS 사이의 라우팅 프로토콜이라는 것, 경로를 알릴 때 그 경로가 지나온 AS의 목록(AS_PATH)을 함께 보낸다는 것, 받은 경로의 AS_PATH에 자기 AS가 있으면 고리로 보고 쓰지 않는다는 것, 경로를 고를 때 지역 정책을 적용한다는 것, TCP 179(이름만). **「경로 벡터(path vector)」라는 이름**을 허용한 출처가 쓰는지와 그 문서·절. 기출 [2024-11-03 #47]·[2026-08-02 #48]이 BGP를 거리 벡터 쪽에 두고 [2026-05-17 #26]이 경로 벡터를 정답으로 두는 문항 사이 모순(`exam-analysis.md`)의 처리 | RFC 4271 §1·§1.1·§3·§5.1.2·§9.1, RFC 4274(BGP-4 프로토콜 분석 — 상태 확인), RFC 1772(옛 적용 문서 — 상태 확인) |

빠진 것을 읽다가 찾으면 더한다. 강의 Ch3-7 p199–p216에서 표준과 다르거나 오해를 부르게 줄여 말한 곳이 더 있으면 같은 방법으로 확인한다.
예를 들어 p201의 「최적 경로」, p202의 「홉: 라우터와 라우터 간의 패킷 이동 과정」(호스트에서 첫 라우터까지도 홉인지), p205의 열 이름과 예, p207의 2진수 비교, p208의 디폴트 라우트 행, p215의 AS 정의(「라우터들의 집단」 — 표준은 접두사·라우터의 묶음이라 하는지), p216 그림의 갈래가 표준과 맞는지 본다.
p203–p204의 `traceroute google.com`·실제 도메인과 주소는 옮기지 않으므로 확인하지 않는다.

### 2. `docs/source/network/standards.md` — 확인한 사실을 더한다

- 기존 항목의 형식을 따른다: `## (phase 74) <문서 이름> — <절 제목>`, URL 한 줄, 직접 쓴 사실 한 줄씩 끝에 `— §절 번호`, 「쓰인 곳」.
  **같은 RFC의 기존 항목(RFC 1812·RFC 4632·RFC 1122 등)이 있으면 새 항목을 만들지 말고 그 항목에 「(phase 74 step 11)」을 붙인 줄로 더한다.**
- 폐기되거나 역사적이 된 RFC(RFC 904·RFC 1058 등)를 쓰면 항목 제목에 그렇다고 붙인다(RFC 1631 항목이 본보기).
- 「쓰인 곳」에는 **쓰일 개념 id**(`routing.ospf` 등)와 수정 이력·exam-notes 번호를 적는다.

### 3. `docs/source/network/lecture-outline.md` — 수정 이력

- 확인 결과 강의가 표준과 다르거나 오해를 부르게 줄여 말했으면 step 0·5가 쓴 마지막 번호 다음부터 「강의 수정 이력」 끝에 더한다. 형식은 L33~L35와 같고 제목 끝에 `[phase 74에서 찾음]`.
- 「강의 수정 이력」 머리의 마지막 phase 문단 뒤에 「phase 74 step 11에서 …」 문단을 더해 무엇을 더했는지(없으면 「Ch3-7에서 새로 찾은 것 없음」)와 표준과 어긋나지 않은 강의 사실을 적는다.
- 「강의별 정리」의 Ch3-7 절에서 해당 줄 끝에 `⚠ L번호`를 단다. 줄의 내용은 강의가 말한 것 그대로 둔다.

### 4. `docs/source/network/exam-notes.md` — 시험의 답이 표준과 다르거나 표준에 없는 곳

이 주제의 기출 문항(`data.txt`의 `routing` 줄)이 정답으로 보는 것이 허용한 출처에 없거나 다르면 이어지는 E번호로 더한다(형식은 E9~ — 시험·표준·처리·쓰인 곳).
표준에 있으면 항목을 만들지 않는다. 이 step이 더한 항목을 소개하는 문단을 새 항목 앞에 둔다(확인한 날 포함).

미리 본 후보 — 확인한 뒤 해당하면 항목으로 남긴다.

- **정적 라우팅의 「부하」와 「우선순위」**([기출 2024-08-25 #13]): 표준에 없으면 처리를 「본문은 표준이 말한 것(사람이 넣고 스스로 바뀌지 않는다, 라우팅 프로토콜 메시지를 주고받지 않는다 — 확인된 것)을 쓰고, 「자격시험은 정적 라우팅이 라우터의 부담이 적고 동적 경로보다 먼저 쓰인다고 본다」를 덧붙인다」로 적는다. 「우선순위」는 업체마다의 설정이라는 것을 허용한 출처로 댈 수 없으면 그 말을 본문 사실로 쓰지 않는다.
- **RIP와 서브넷**([기출 2024-02-25 #9]): 시험이 「서브넷 주소를 인식한다」를 틀린 보기로 둔다. RIPv2가 마스크를 싣는다면, 처리를 「본문은 RIPv1·RIPv2의 차이를 표준대로 쓰고, 「자격시험은 RIP의 특징으로 RIPv1의 성질(서브넷 마스크를 싣지 않는다)을 묻기도 한다」를 덧붙인다」로 적는다.
- **BGP를 거리 벡터 쪽에 둔 문항**([기출 2024-11-03 #47], [기출 2026-08-02 #48]): 두 문항의 정답(OSPF)은 맞으므로 「자격시험은」 줄을 쓰지 않는다. 처리를 「본문은 BGP를 경로 벡터로 쓴다. 두 문항의 보기 구성은 같은 시험의 다른 문항([기출 2026-05-17 #26])과 어긋나 문항 쪽의 흠으로 기록만 한다」로 적는다.
- **IGRP**: 기출 보기에 거리 벡터 프로토콜로 나온다. 시스코가 만든 프로토콜이고 허용한 출처에 문서가 없으면 개념·문항에 쓰지 않는다고 적는다.

### 5. summary — 뒤 step이 이것을 보고 쓴다

`routing`의 개념 9개마다 한 줄씩: **무엇을 쓸 수 있는지(출처와 함께), 무엇을 고쳐 쓰는지(L번호), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호)**.
위 표의 a~i마다 결과(확인함/강의가 맞음/못 찾음)와 근거 문서를 적는다. 못 찾은 것은 무엇을 어디서 찾아봤는지 적는다. 끝에 「사용자 확인」 칸을 둔다(없으면 「없음」).

- **허용한 출처 밖의 문서(위키백과·블로그·자격증 교재·업체 학습 페이지, 시스코 문서, 강의가 가리킨 AS 번호 목록 페이지)를 근거로 쓰지 마라.** 이유: ADR-059. 시스코 제품 문서는 VTP에만 허용했다.
- **강의·기출·표준 문서의 문장을 옮기지 마라.** 이유: ADR-009·ADR-057.
- **라우팅 테이블을 보는 명령의 옵션·출력 읽기를 정리하지 마라.** 이유: `diagnostic-commands` 주제(phase 78)의 범위다. 이 step은 명령의 이름만 확인한다.
- **`docs/source/network/CLAUDE.md`·`topic-map.md`를 고치지 마라.** 이유: 이 step이 쓰는 출처는 모두 이미 허용한 곳(IETF RFC·IANA·man7.org·learn.microsoft.com)이다.
