# Step 4: subnetting-sizing

## 배경

phase 74는 네트워크 과목의 `ip-addressing`·`ip-address-types`·`routing`을 만든다. 전체 계획·결정·공통 규칙은 `phases/74-network-addressing-routing/guide.md`에 있다.
**이 step은 주제 `ip-addressing`에 마지막 개념 둘(7 서브네팅, 8 서브넷 수와 호스트 수)의 글·문항·도식을 더해 주제를 마무리한다.** 개념 1~6은 step 1~3이 만들었다.

기출 `ip-addressing` 19문항 가운데 11문항이 이 두 개념의 계산이다 — 서브넷의 호스트 수, 서브넷의 마지막 사용 가능 주소·브로드캐스트 주소, 필요한 서브넷 수나 호스트 수에 맞는 마스크.
학습자가 이 화면만 읽고 그 계산을 스스로 할 수 있어야 한다.

## 작업

### 1. 개념 — `src/data/network/topics.json`의 `ip-addressing`에 덧붙인다

| # | id | name | parentId | 이 step에서 특히 |
|---|---|---|---|---|
| 7 | `ip-addressing.subnetting` | 서브네팅 | — | 무엇인가(네트워크 하나를 더 작은 네트워크 여럿으로 나누는 것, 나뉜 네트워크를 서브넷이라 한다) → 어떻게(호스트 부분의 앞쪽 비트를 네트워크 쪽으로 넘겨 마스크를 길게 한다) → 몇 개로(넘긴 비트 k개 → 서브넷 2^k개, 서브넷마다 주소 2^(남은 호스트 비트)개). 예를 처음부터 끝까지 — `192.0.2.0/24`에서 2비트를 넘겨 `/26` 넷(`192.0.2.0`·`192.0.2.64`·`192.0.2.128`·`192.0.2.192`), 각 64개 주소. 그 가운데 `192.0.2.64/26` 하나의 네트워크 주소 `.64`, 호스트에 줄 첫 주소 `.65`·끝 주소 `.126`, 브로드캐스트 주소 `.127`을 개념 2의 규칙으로 구한다. 서브넷의 시작 주소가 64씩 늘어나는 까닭(블록 크기). 서브넷 번호가 모두 0·모두 1인 서브넷의 옛 규칙은 step 0 결과대로 — 본문은 지금 규칙(2^k)으로 센다 |
| 8 | `ip-addressing.subnet-sizing` | 서브넷 수와 호스트 수 | `subnetting` | 필요한 수에서 마스크를 고르는 두 길. (1) 서브넷이 N개 필요하면 2^k ≥ N인 가장 작은 k비트를 넘긴다. (2) 서브넷마다 호스트가 M대 필요하면 2^h − 2 ≥ M인 가장 작은 호스트 비트 h를 남긴다. 접두사 길이별 주소 수·호스트 수·마스크 넷째 옥텟을 계산으로 보인다(`/26` 64·62·192, `/27` 32·30·224, `/28` 16·14·240, `/29` 8·6·248, `/30` 4·2·252) — 표를 외우게 하지 말고 2의 거듭제곱에서 나온다는 것을 보인다. 예 둘 — 호스트 10대 → h = 4(14 ≥ 10) → `/28`·`255.255.255.240`, C 클래스 크기 네트워크를 서브넷 6개로 → k = 3(8 ≥ 6) → `/27`·`255.255.255.224`. 기출이 묻는 B 클래스 크기를 나누는 예 하나 — 「앞 16비트가 네트워크인 네트워크」를 서브넷 6개로 나누면 셋째 옥텟에서 3비트를 넘겨 `255.255.224.0`(주소 없이) |

### 2. 문항 — `src/data/network/questions.json`에 `n087`~`n089`

| id | 개념 | 방향(바꿀 수 있다 — 바꾸면 이유를 summary에) |
|---|---|---|
| `n087` | `subnetting` | 4지선다 「상황 적용」 감 — 본문 예와 다른 문서용 네트워크·접두사 길이(예: `198.51.100.0/24`를 `/27`로 나눈 상황)에서 어떤 주소가 속한 서브넷의 브로드캐스트 주소나 마지막 사용 가능 주소를 고른다. 오답은 흔한 실수에서 — 블록 경계를 하나 잘못 잡은 값, 브로드캐스트와 마지막 사용 가능 주소를 바꾼 값, 원래 네트워크 전체의 브로드캐스트 주소 |
| `n088` | `subnet-sizing` | 4지선다 「상황 적용」 감 — 서브넷마다 필요한 호스트 수(본문 예와 다른 수)를 주고 주소를 가장 적게 남기는 마스크를 고른다. 오답은 2를 빼지 않아 모자라는 마스크, 넉넉하지만 가장 작지 않은 마스크, 비트를 하나 더 넘긴 마스크. 「가장 적게 남기는」 같은 판단 조건을 문제문에 준다 |
| `n089` | `subnet-sizing` | 4지선다 「상황 적용」 감 — 필요한 서브넷 수(본문 예와 다른 수)를 주고 마스크를 고른다. n088과 다른 길(서브넷 수에서 고르기)을 묻는다. 「앞 16비트가 네트워크인 네트워크」처럼 주소 없이 줄 수 있다 |

### 3. 도식

#### 3-1. `ip-addressing.subnetting` — `SubnettingDiagram`, JSON 키 `subnetting`

- 물음형 제목 예: `네트워크 하나를 넷으로 나누면 주소가 어떻게 갈릴까?`
- 그릴 것: 위에 원래 네트워크 노드 `192.0.2.0/24`, 아래에 서브넷 노드 넷(`192.0.2.0/26`·`192.0.2.64/26`·`192.0.2.128/26`·`192.0.2.192/26`). 원래 네트워크에서 서브넷마다 이어지는 경로.
- 시나리오:

  | id | label | 선명한 것 | 캡션이 말할 것 |
  |---|---|---|---|
  | `split` | 넷으로 나누기 | 원래 네트워크와 서브넷 넷 | 호스트 부분에서 2비트를 넘기면 2² = 4개의 서브넷이 생기고 서브넷마다 주소는 64개다 |
  | `range` | 서브넷 하나의 범위 | `192.0.2.64/26` | 이 서브넷의 네트워크 주소는 `.64`, 호스트에 주는 주소는 `.65`~`.126`, 브로드캐스트 주소는 `.127`이다 |

- 요점 테스트: `split`에서 선명한 서브넷 노드가 넷이고 라벨의 넷째 옥텟이 0·64·128·192다. `range`의 선명한 서브넷 노드는 `192.0.2.64/26` 하나이고, 보이는 곁말에 `.65`·`.126`·`.127`이 있다.

#### 3-2. `ip-addressing.subnet-sizing` — `SubnetSizingDiagram`, JSON 키 `subnet-sizing`

- 물음형 제목 예: `필요한 호스트 수와 서브넷 수에 맞는 마스크는 어떻게 고를까?`
- 그릴 것: 접두사 길이마다 한 줄(`/26`~`/30`) — 접두사 노드, 마스크 노드(`255.255.255.192` 등), 곁말(호스트 수 62·30·14·6·2).
- 시나리오:

  | id | label | 선명한 것 | 캡션이 말할 것 |
  |---|---|---|---|
  | `by-hosts` | 호스트 10대 | `/28` 줄 | 2⁴ − 2 = 14가 10 이상인 가장 작은 크기라서 `/28`을 고른다 |
  | `by-subnets` | 서브넷 6개 | `/27` 줄 | 2³ = 8이 6 이상이라 3비트를 넘겨 `/24`가 `/27`이 된다 |

- 요점 테스트: `by-hosts`의 선명한 줄이 `/28` 하나이고 그 마스크 노드 라벨이 `255.255.255.240`이다. `by-subnets`의 선명한 줄은 `/27` 하나이고 마스크가 `255.255.255.224`다. 호스트 수 곁말이 2의 거듭제곱에서 2를 뺀 값이다(62·30·14·6·2).

위 도식 설계는 출발점이다. 본문(step 0 결과)과 맞지 않거나 280 폭에 들지 않으면 바꾸되, 바꾼 것과 이유를 summary에 적는다. 시나리오의 사실이 본문에 없으면 그 시나리오를 빼고 summary에 적는다.

## 금지사항

guide.md 「모든 step의 공통 금지」에 더해:

- **`ip-address-types`·`routing`의 개념을 만들지 마라.** 이유: step 6~10, 12~16의 범위다.
- **강의가 가리킨 온라인 서브넷 계산기나 그 결과 화면의 주소(`192.168.100.103/30`)를 옮기지 마라.** 이유: 허용한 출처가 아니고(ADR-059), 예시 값은 문서용 대역에서 만든다(guide.md 「예시 값」).
- **서브넷 수를 옛 규칙(2^k − 2)으로 가르치지 마라.** 이유: guide.md 개념 표 7 — 본문은 지금 규칙으로 센다. 옛 규칙은 step 0이 확인한 만큼만 한 줄로 쓴다.
