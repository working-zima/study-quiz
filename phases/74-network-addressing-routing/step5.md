# Step 5: address-types-sources

## 배경

phase 74는 네트워크 과목의 `ip-addressing`·`ip-address-types`·`routing`을 만든다. 전체 계획과 결정은 `phases/74-network-addressing-routing/guide.md`에 있다.
step 6~10이 `ip-address-types`의 개념 9개를 쓰기 전에, **이 step은 그 개념들이 쓸 사실 가운데 강의 밖이거나 강의가 틀렸을 수 있는 것을 표준·공식 문서로 확인하고 출처 문서에 남긴다.**
데이터·코드는 고치지 않는다. 뒤 step은 이 step이 남긴 기록과 summary를 보고 무엇을 쓰고 무엇을 쓰지 않을지 정한다. `ip-addressing`(step 0~4)은 이미 끝났다.

`ip-address-types`는 기출 21문항이 거의 강의 사실(NAT 6, DHCP 7, 사설 대역 4, 루프백 4)이지만, 기출 보기에는 표준에 없을 수 있는 말이 섞여 있다 —
NAT의 「보안상 이점」, 「PAT」라는 이름, 「서버·프린터는 고정 주소」, DHCP의 할당 방식 셋. 그 처리는 **이 step이 정한 대로만** 뒤 step이 쓴다.

## 작업

### 1. 확인할 것 — 하나씩 허용한 출처를 실제로 열어 확인한다

볼 곳은 `rfc-editor.org`(RFC 본문 — 텍스트판을 받아 절을 직접 읽는다)와 `iana.org`(레지스트리)가 중심이고, Windows의 동작은 `learn.microsoft.com`이다.
RFC는 지금 유효한 것을 쓰고, 폐기되거나 역사적이 된 RFC는 역사 기록으로만 쓰고 그렇다고 밝힌다. 위키백과·블로그·업체 학습 페이지는 쓰지 않는다.

| # | 개념 | 확인할 것 | 볼 곳(예) |
|---|---|---|---|
| a | `public-address` | 공인 주소가 전역에서 하나뿐이도록 IANA → 지역 인터넷 등록 기관(RIR) → (나라 기관 NIR·지역 등록 기관 LIR) → 사용자 차례로 나눠 준다는 것. RIR의 이름 하나(아시아·태평양은 APNIC). 한국의 KISA는 강의 p185의 사실로만 쓸 수 있는지(강의 그림이 무엇을 보이는지 렌더해서 본다) | RFC 7020 §2·§3, IANA 「IPv4 Address Space Registry」, RFC 1918 §1(전역 주소) |
| b | `private-address` | 사설 대역 셋과 그 범위(이미 있다 — 172.16.0.0~172.31.255.255처럼 끝 주소를 계산으로 보일지), 사설 주소는 여러 조직이 겹쳐 쓸 수 있다는 것, 인터넷 쪽 라우터가 사설 주소로 가는 경로를 받지 않는다는 것(이미 있다), 사설 주소를 쓰는 호스트가 바깥과 통신하려면 주소 변환(NAT)이나 다른 수단이 필요하다는 것 | RFC 1918 §3·§4(이미 있는 항목에 더한다) |
| c | `reserved-addresses` | IANA의 특수 용도 IPv4 주소 레지스트리의 이름과, 이 phase가 쓸 항목 — `0.0.0.0/8`(이 네트워크·주소를 아직 모를 때 출발지로), `127.0.0.0/8`, `169.254.0.0/16`(링크 로컬 — 주소를 받지 못한 호스트가 스스로 정하고, 라우터가 넘기지 않는다), 문서용 셋(이미 있다), `255.255.255.255`(제한된 브로드캐스트 — 라우터가 넘기지 않는다). `224.0.0.0/4`(멀티캐스트)와 `240.0.0.0/4`(예약)는 step 0이 확인한 D·E 클래스와 같은 범위인지. Windows가 DHCP 서버를 찾지 못하면 `169.254`의 주소를 스스로 정한다는 것(자동 개인 IP 주소 지정, APIPA)을 공식 문서로 댈 수 있는지 | IANA 「IPv4 Special-Purpose Address Registry」, RFC 6890, RFC 1122 §3.2.1.3, RFC 3927 §1·§2.6·§7, RFC 919 §7·RFC 922, RFC 1812 §5.3.5, learn.microsoft.com(Windows의 자동 주소 지정 문서) |
| d | `loopback` | `127.0.0.0/8`로 보낸 데이터그램은 호스트 밖 네트워크로 나가지 않는다는 것과 그 근거 절. 루프백으로 자기 호스트의 네트워크 소프트웨어를 시험한다는 것을 표준으로 댈 수 있는지(없으면 위 사실에서 나오는 쓰임이라고 적고 「자격시험은 루프백 테스트라 부른다」로 처리할지 정한다). `localhost`라는 이름이 루프백 주소를 가리킨다는 것 | RFC 1122 §3.2.1.3(g), RFC 6890, RFC 6761 §6.3, RFC 5735(폐기 — 역사 기록) |
| e | `nat` | NAT가 하는 일 — 경계의 라우터가 IP 헤더의 주소를 바꾸고 그 대응을 기억한다는 것(이미 있는 RFC 3022에 더한다). NAT는 IP 헤더(와 필요하면 체크섬)를 고치므로 네트워크 계층의 일이라는 근거. **정적·동적 주소 대응**의 뜻과 이름(주소를 1:1로 고정해 대응시키는 방식 / 공인 주소 묶음에서 그때그때 대응시키는 방식). L7(완화)의 처리 확인. 기출 보기 「NAT는 안쪽 주소 구조를 바깥에 드러내지 않아 보안상 이점이 있다」·「보안을 강화할 수 있다」를 표준이 어떻게 말하는지 — NAT가 보안 장치가 아니라고 하는지, 「주소를 숨긴다」를 어떻게 다루는지 | RFC 3022 §1·§2·§4, RFC 2663 §2·§3·§4·§9(보안 고려), RFC 4864 §2(NAT가 준다고 여겨지는 이점) |
| f | `napt` | NAPT의 뜻(이미 있다 — RFC 3022 §2.2·§3.1)과 그것이 공인 주소 하나를 여럿이 함께 쓰게 하는 방법(포트로 가른다). 포트를 한 줄로 풀 근거(전송 계층이 한 호스트 안의 통신을 가르는 번호). **기출의 이름 「PAT」**가 허용한 출처에 있는지 — 없으면 「자격시험은 이 방식을 PAT(포트 주소 변환)라고도 부른다」로 처리 | RFC 3022 §2.2·§3.1, RFC 2663 §4.1.2, RFC 9293 §3.1 또는 RFC 768(포트 — 이미 있는 항목) |
| g | `static-dynamic-address` | 정적 할당(사람이 직접 정한다)과 동적 할당(DHCP로 받고 바뀔 수 있다)의 근거. **「다른 장치가 늘 같은 주소로 찾아와야 하는 서버·네트워크 프린터에는 고정 주소를 쓴다」**를 공식 문서로 댈 수 있는지 — DHCP의 수동 할당·예약(reservation)을 설명하는 문서가 그 쓰임을 말하는지 본다. 없으면 「자격시험은 ~로 본다」로 처리 | RFC 2131 §1, learn.microsoft.com(DHCP 예약 문서) |
| h | `dhcp` | DHCP가 주는 것(IP 주소와 설정 — 서브넷 마스크, 라우터(기본 게이트웨이), DNS 서버의 옵션 번호와 이름), 임대(정해진 시간 동안 빌려준다)와 갱신. **할당 방식 셋**(자동 — 영구히 준다, 동적 — 정해진 시간 동안 빌려준다, 수동 — 관리자가 정한 주소를 DHCP가 전한다)의 이름과 뜻. 서버·클라이언트의 UDP 포트 번호(67·68). DHCP가 BOOTP를 바탕으로 한다(이미 있다). p194 화면의 칸(임대 시작·만료, 기본 게이트웨이, DHCP 서버)이 표준과 맞는지 | RFC 2131 §1·§2·§3·§4.1, RFC 2132 §3.3·§3.5·§3.8·§9.2, IANA 「Service Name and Transport Protocol Port Number Registry」 |
| i | `dhcp-messages` | 처음 주소를 받을 때의 메시지 넷(DHCPDISCOVER·DHCPOFFER·DHCPREQUEST·DHCPACK)과 그 차례, 누가 누구에게 보내는지. 주소가 없는 클라이언트가 DISCOVER를 브로드캐스트로 보낸다는 것과 그때의 출발지·목적지 주소(`0.0.0.0`·`255.255.255.255`). REQUEST도 브로드캐스트로 보내는 까닭(여러 서버 가운데 고른 것을 모두에게 알린다). 갱신할 때(임대 시간의 절반쯤 — T1)는 서버에게 바로 REQUEST를 보낸다는 것. DHCPNAK·DHCPRELEASE는 이름만 | RFC 2131 §3.1·§3.2·§4.1·§4.4.5 |

빠진 것을 읽다가 찾으면 더한다. 강의 Ch3-6 p180–p198에서 표준과 다르거나 오해를 부르게 줄여 말한 곳이 더 있으면 같은 방법으로 확인한다.
예를 들어 p186–p187 예약 주소 표의 이름과 범위, p189의 NAT 설명(L7 — 이미 있다), p192–p193의 「동적 IP 주소를 할당하기 위한 프로토콜」, p195의 메시지 이름(「Acknowledgement」)과 화살표 방향이 표준과 맞는지 본다.

### 2. `docs/source/network/standards.md` — 확인한 사실을 더한다

- 기존 항목의 형식을 따른다: `## (phase 74) <문서 이름> — <절 제목>`, URL 한 줄, 직접 쓴 사실 한 줄씩 끝에 `— §절 번호`, 「쓰인 곳」.
  **같은 RFC의 기존 항목(RFC 1918·RFC 3022·RFC 1122·RFC 919·RFC 1812·RFC 951/RFC 2131 등)이 있으면 새 항목을 만들지 말고 그 항목에 「(phase 74 step 5)」를 붙인 줄로 더한다.**
  RFC 2131 항목의 머리 「RARP와의 관계만 가져온다」는 phase 73의 기록이다 — 고치지 말고 「(phase 74 step 5)」 줄이 DHCP의 동작을 더한다는 것을 그 아래에 밝힌다.
- 폐기되거나 역사적이 된 RFC를 쓰면 항목 제목에 그렇다고 붙인다(RFC 1631 항목이 본보기).
- 「쓰인 곳」에는 **쓰일 개념 id**(`ip-address-types.nat` 등)와 수정 이력·exam-notes 번호를 적는다.

### 3. `docs/source/network/lecture-outline.md` — 수정 이력

- 확인 결과 강의가 표준과 다르거나 오해를 부르게 줄여 말했으면 step 0이 쓴 마지막 번호 다음부터(step 0이 더하지 않았으면 `L36`부터) 「강의 수정 이력」 끝에 더한다. 형식은 L33~L35와 같고 제목 끝에 `[phase 74에서 찾음]`.
- 「강의 수정 이력」 머리의 마지막 phase 문단 뒤에 「phase 74 step 5에서 …」 문단을 더해 무엇을 더했는지(없으면 「Ch3-6에서 새로 찾은 것 없음」)와 표준과 어긋나지 않은 강의 사실을 적는다.
- 「강의별 정리」의 Ch3-6 절에서 해당 줄 끝에 `⚠ L번호`를 단다. 줄의 내용은 강의가 말한 것 그대로 둔다.

### 4. `docs/source/network/exam-notes.md` — 시험의 답이 표준과 다르거나 표준에 없는 곳

이 주제의 기출 문항(`data.txt`의 `ip-address-types` 줄)이 정답으로 보는 것이 허용한 출처에 없거나 다르면 이어지는 E번호로 더한다(형식은 E9~ — 시험·표준·처리·쓰인 곳).
표준에 있으면 항목을 만들지 않는다. 이 step이 더한 항목을 소개하는 문단을 새 항목 앞에 둔다(확인한 날 포함).

미리 본 후보 — 확인한 뒤 해당하면 항목으로 남긴다.

- **NAT의 보안**([기출 2025-11-02 #49]의 맞는 보기, [기출 2025-08-24 #10]): 표준이 「주소를 숨기는 효과」와 「NAT는 보안 장치가 아니다」를 어떻게 말하는지에 따라, 본문이 쓸 수 있는 문장과 「자격시험은」 줄을 정한다.
- **「PAT」라는 이름**([기출 2025-11-02 #49]): 허용한 출처에 없으면 「자격시험은 NAPT를 PAT라고도 부른다」.
- **고정 주소를 쓸 장치**([기출 2024-05-19 #12], [기출 2024-11-03 #28], [기출 2025-08-24 #13]): 공식 문서에 근거가 없으면 「자격시험은 서버·네트워크 프린터처럼 늘 같은 주소로 찾아야 하는 장치에는 고정 주소를, 사용자 PC에는 DHCP를 쓰는 것이 맞다고 본다」.
- **DHCP 할당 방식**([기출 2026-08-02 #17]): RFC 2131 §1에 셋이 있으면 항목을 만들지 않는다.

### 5. summary — 뒤 step이 이것을 보고 쓴다

`ip-address-types`의 개념 9개마다 한 줄씩: **무엇을 쓸 수 있는지(출처와 함께), 무엇을 고쳐 쓰는지(L번호), 무엇을 쓰지 않는지, 「자격시험은」 줄이 필요한지(E번호)**.
위 표의 a~i마다 결과(확인함/강의가 맞음/못 찾음)와 근거 문서를 적는다. 못 찾은 것은 무엇을 어디서 찾아봤는지 적는다. 끝에 「사용자 확인」 칸을 둔다(없으면 「없음」).

- **허용한 출처 밖의 문서(위키백과·블로그·자격증 교재·업체 학습 페이지, 강의가 가리킨 KISA 페이지)를 근거로 쓰지 마라.** 이유: ADR-059. KISA는 강의 그림이 보이는 사실로만 쓸 수 있다.
- **강의·기출·표준 문서의 문장을 옮기지 마라.** 이유: ADR-009·ADR-057.
