## 설계와 달라진 것

모두 step summary에 이유가 있고, 받아들였다.

- **개념 3의 이름을 「사용량 기반 모델」로**(step 4). 한국어판 Learn 단원이 「소비 기반 모델」과 「사용량 기반 모델」을 섞어 쓰는데, 본문은 「사용량 기반 모델」로 쓰고 「소비 기반 모델이라고도 옮긴다」를 한 줄 붙였다.
- **「스폿」 표기**(step 4·6). Microsoft 한국어 문서는 「스폿」이다. step 문서의 「스팟」을 따르지 않았다.
- **「온-프레미스」 표기**(step 7). 받은 한국어판 어디에도 붙여 쓴 「온프레미스」가 없어, guide의 잠정 표기 대신 하이픈을 넣은 「온-프레미스」로 쓴다.
- **서버 풀이**(step 5). 「다른 컴퓨터의 요청을 받아 일을 해 주는 컴퓨터」를 공식 문서에서 찾지 못해 「프로그램을 설치해 실행할 컴퓨터」로 썼다.
- **가격 모델 표의 둘째 열을 「가격과 조건」으로**(step 6). 스폿 VM에 기간 약정이 없다는 문장을 공식 문서에서 찾지 못해 「미리 약속하는 것」 열을 세울 수 없었다.

## 사용자가 볼 것

출처 step 둘(4·7)을 포함해 모든 step의 「사용자 확인」은 「없음」이다(step 8 summary에는 그 칸이 없고, 내용상 확인할 것이 없다). 아래는 출처 step이 공식 문서에 비춰 정했고 ADR-060의 규칙(충돌하면 공식 문서)대로라 사용자 결정이 필요하지 않다고 봤다.

- **D11 — 「데이터 센터를 없앨 수 있는 모델」.** 덤프가 NO.30·238(퍼블릭)과 NO.272(프라이빗)로 갈린다. 공식 문서는 데이터 센터의 존폐를 모델과 짝짓지 않으므로, 본문은 「하드웨어와 그것을 둔 데이터 센터를 누가 갖추고 관리하나」로 쓰고 두 결론 문장 어느 쪽도 쓰지 않는다.
- **D12 — 덤프끼리 갈린 NO.283·NO.370.** 공식대로 예·예·아니요.
- **D14 — 「하이브리드가 비용을 가장 줄인다」(NO.277).** 공식 문서에 없어 「가장 싸다」를 쓰지 않는다.
- 용어집의 「멀티 클라우드」는 쓰지 않고 Microsoft 한국어 문서의 「다중 클라우드」로 쓴다. 주제 제목은 주제 지도대로 「클라우드 배포 모델」(한국어판 단원 제목은 「클라우드 모델」).
