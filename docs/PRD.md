# PRD: Study Quiz

## 목표

과목별로 개념을 주제 단위로 읽고, 읽은 자리에서 바로 확인 문제로 이해도를 점검하는 학습 앱이다.
**문제를 많이 푸는 앱이 아니라 개념이 남는 앱을 만든다.**

지금 담긴 과목은 AWS SAA-C03 하나다 — SAA-C03 범위의 AWS 서비스 개념. 과목 구조는 ADR-053이 정한다.
**이 문서의 나머지(사용자·원본·핵심 기능의 수치·문제 은행)는 AWS 과목의 것이다.** 앱 전체에 걸리는 것은
과목을 고르는 방식과, 검색·랜덤·복습·진행률이 과목 안에서만 돈다는 것(핵심 기능 8)이다.

## 사용자

SAA-C03을 준비하는 사람. AWS 서비스 이름은 들어봤지만 "언제 무엇을 쓰는지"가
정리되지 않은 상태. 짧게 여러 번 들여다보며 개념을 눌러 담는 방식으로 공부한다.

## 원본

출처는 넷이다. 여기 없는 내용은 만들지 않는다.

1. `docs/source/concepts-raw.md` — 원본 PDF에서 추출한 22개 주제의 개념 정리.
   각 주제에는 원본이 매긴 중요도(★★★ / ★★☆)가 붙어 있었고, ADR-051부터는 아래 「강조 기준」의 우선순위로 다시 매긴다.
   **문제는 전부 이 문서에서만 나온다.**
2. `docs/source/exam-gaps.md` — 163문항 덤프 해설에서 위 개념 텍스트에 없는 정답 근거만 추린 것.
   근거는 ADR-008.
3. `docs/source/service-categories.md` — AWS 백서에서 뽑은 카테고리 이름과 서비스 배치.
   개념 본문의 카테고리 한 줄에만 쓴다. 근거는 ADR-019·ADR-022.
4. `docs/source/dump-gaps/` — 880문항 덤프 해설집에서 위 셋에 없는 정답 근거만 추린 것.
   근거는 ADR-021. **여기서는 개념만 가져오고 문항은 가져오지 않는다** — 복수정답이 섞여 있어
   문항은 정답이 하나라는 규칙(ADR-005·ADR-054)과 어긋나기 때문이다.

**강조 기준** — `docs/source/exam-types.md`(JSCODE 노션 「시험 문제 출제 유형」을 직접 쓴 말로 정리한 것)는 사실의 출처가 아니다.
무엇을 강조할지(주제 별점, 개념 본문의 굵은 글씨, 「A vs B」 제목)를 고르는 데만 쓴다. 근거는 ADR-051.

## 핵심 기능

1. **주제 목록** — 과목의 주제(AWS는 39개)를 중요도와 함께 보여준다. 각 주제의 학습 상태(안 봄 / 읽음 / 점검 완료)를 표시한다.
2. **개념 읽기** — 주제 하나의 개념을 처음부터 끝까지 읽는 화면. 서비스별로 "한 줄 요약 → 설명 → 특징" 순서로 정리한다.
3. **확인 문제** — 개념을 읽은 뒤 그 주제의 문제를 푼다. 형식은 4지선다나 예/아니요이고, 정답은 하나다. 문항 순서와 4지선다의 보기 순서는 열 때마다 섞이고, 예/아니요 버튼은 「예」「아니요」 순서 그대로다(ADR-054). 답을 고르면 즉시 정오 표시 + 해설, 그리고 근거가 된 개념으로 돌아가는 링크.
4. **복습** — 문제를 푼 뒤 사용자가 고른 문항을 복습 목록에 모아 두고, 그 문항만 다시 푼다. 문항마다 근거 개념으로 가는 링크가 붙는다. **틀렸다고 저절로 들어오지 않고, 다시 맞혔다고 저절로 빠지지 않는다** — 넣고 빼는 것은 사용자다. 근거는 ADR-017·ADR-032.
5. **진행률** — 주제별 / 전체 학습 진행 상황. localStorage에 저장해 브라우저를 닫아도 유지된다.
6. **랜덤 문제** — 주제와 무관하게 전체 문항에서 10 / 20 / 30 / 50 / 100개나 전체를 무작위로 뽑아 푼다. 푸는 화면과 기록은 확인 문제와 같고, 다른 것은 문항을 고르는 범위뿐이다. 주제 이름이라는 힌트 없이 서비스를 구분할 수 있는지 점검하는 용도다. 근거는 ADR-012.
7. **검색** — 개념 이름·한 줄 요약·본문과 주제 제목에서 찾는다. 결과는 그 개념이 속한 주제의 개념 읽기로 이어진다. 개념 640개는 주제 제목만 봐서는 어디 있는지 알 수 없기 때문이다. **문항은 검색하지 않는다** — 문제문과 해설이 결과에 뜨면 확인 문제가 무의미해진다. 근거는 ADR-013.
8. **과목** — 첫 화면에서 과목을 고른다. 과목마다 이름과 주제·문항 수만 적힌 카드가 하나씩 있다. 고른 과목 안에서는 주제 목록 맨 위의 「모든 과목」으로 첫 화면에 돌아온다. **검색·랜덤·복습·진행률은 과목 안에서만 돈다** — 다른 과목의 개념이 검색되거나, 랜덤 세트에 섞이거나, 복습 목록과 진행률에 들어오지 않는다. 마지막으로 연 과목을 기억하거나 헤더에서 과목을 전환하지 않는다. 근거는 ADR-053.

## MVP 제외 사항

- 모의고사 · 제한시간 · 점수 산출. 이유: 시험 리허설은 이 앱의 목적이 아니다.
  랜덤 문제(핵심 기능 6)는 이 선 안쪽이다 — 범위만 전체로 넓힌 확인 문제이고,
  제한시간도 합격선도 점수 이력도 두지 않는다. 셋 중 하나라도 붙는 순간 이 제외 사항을 어긴 것이다.
- 복수정답 문제. 이유: 형식은 4지선다와 예/아니요 둘이고, 둘 다 정답이 하나다(ADR-005·ADR-054).
- 주관식(단답형·설명형). 이유: 사용자가 뺐다. 명칭·정의는 4지선다 「정의 → 이름」으로, 요소 사이 관계는 도식과 「왜·다음 단계」를 묻는 문항으로
  점검한다. 대가로 명칭은 떠올리기가 아니라 알아보기로만 점검한다(ADR-054).
- 계정 · 로그인 · 서버 · 기기 간 동기화. 이유: 서버를 두지 않는 게 배포 전략이다.
- 런타임 AI 문제 생성. 이유: 문제 은행은 빌드 전에 확정해 JSON으로 커밋한다.
- 검색 — **ADR-013으로 개정됐다. 핵심 기능 7을 봐라.** 원래 사유는 주제가 20개이던 때
  "목록으로 훑는 게 더 빠르다"고 본 것이었고, ADR-013이 개정한 것은 그 안에 든
  **개념을 이름으로 찾는 경로** 하나뿐이었다. 문항 본문·해설 검색은 여전히 제외다.
  **그 사유의 전제가 흔들렸다** — 주제가 39개, 개념이 618개가 됐고(ADR-023) 지금은 640개다.
  주제를 목록으로 훑는 것이 지금도 빠른지는 실물을 보고 정할 일이므로 **여기서 결론 내지 않는다.**
  주제 목록에 필터를 붙일지 말지는 **열린 문제로 남기고, 정해지기 전까지는 붙이지 마라.**

## 문제 은행

- **크기 기준은 개념 커버리지다 — 개념 하나에 최소 1문항.** 출제되지 않은 개념을 남기지 않는다.
  실측은 `node scripts/coverage.mjs`가 낸다.
- 전에는 **"총 169문항 목표, 22개 주제에 중요도 비례로 배분"** 이었다. 개념이 182개이던 때의
  기준이라 대체했다 — 이 앱의 주 학습 경로는 문제를 풀고 틀린 것만 개념으로 되짚는 순환이므로,
  문항이 가리키지 않는 개념은 그 경로에서 아예 배울 수 없다. **중요도는 무엇을 먼저 읽을지를
  정하는 값이고, 무엇이 배워지는지를 정하는 값은 커버리지다.** 근거는 ADR-026.
- 출제 근거는 위 「원본」의 네 출처다. 개념 본문이 이미 그 출처에서 나왔으므로 **문항은 개념
  본문이 담고 있는 사실에서만 만든다.** 원본에 없는 AWS 지식을 끌어오지 마라.
  (전에는 이 줄이 `concepts-raw.md` 하나만 가리켰다. 개념 618개 중 436개가 `dump-gaps/`에서
  왔으므로 그대로 두면 그 개념들은 출제 자체가 막힌다.)
- 각 문항은 반드시 근거 개념(주제 id + 개념 id)을 필드로 갖는다. 해설에서 개념으로 되돌아가기
  위해 필요하고, 커버리지를 세는 것도 이 필드다.
- **해설은 정답을 정당화하는 글이 아니라 그 개념을 가르치는 글이다.** 정답이 왜 맞는지와 함께
  오답이 왜 아닌지를 담는다. 문제만 푸는 사용자에게는 해설이 유일한 설명 텍스트이고, 문항
  순서가 열 때마다 섞이며(ADR-011) 랜덤 세트는 일부만 뽑으므로(ADR-012) **앞 문항의 해설이
  설명해 줬을 것이라고 가정할 수 없다.** 각 해설은 단독으로 읽혀 그 개념이 남아야 한다.
  **짧게 줄이지 마라** — "A가 맞다" 수준의 한 줄은 이 규칙을 어긴 것이다.
- 오답 선택지도 원본에 등장하는 다른 서비스에서 고른다. 그래야 "헷갈리는 짝"을 구분하는 연습이 된다.
- **정답 계열을 가리키는 키워드는 문제문에 일관되게 넣되, 그 키워드만으로 답이 정해지게 두지 마라.**
  예: Glacier 계열이 정답인 문항은 모두 문제문에 법·감사(·규정) 목적을 담는다(원본 PAGE 8 근거).
  대신 그런 문항의 보기에는 **Glacier 보기를 둘 이상** 두어, 최종 판단은 조회 시간 같은 실제
  변별 축이 하게 한다. 보기 중 Glacier가 하나뿐이면 키워드가 곧 정답이 되어 문항이 무의미해진다.
- **키워드를 부정형으로 쓰는 대조 문항을 함께 둔다.** q018("법·감사 목적의 장기 보관은 아니면서",
  정답 S3 Standard-IA)이 그것이다. 이런 문항이 있어야 "법이 보이면 무조건 Glacier"라는
  잘못된 암기가 걸러진다. 지우지 마라.
- **개념 640개가 전부 문항으로 덮였다(100%).** 문제 은행은 246문항에서 phase 27이 `q247`~`q732`
  486문항을 더해 732문항이 됐고, 그 뒤 새 개념과 함께 더한 `q733`~`q746`까지 지금 **746문항**이다.
  **문항이 하나도 없는 주제는 없다** — 39개 주제 중 가장 적은 `governance-iac`·`ai-ml-services`가
  7문항, 가장 많은 `sqs-sns-eventbridge`가 41문항이다. ADR-023이 "문항을 어디까지 채울지"를 열린
  문제로 남겼고 **ADR-026이 그것을 닫았다.**
- **커버리지 100%는 이제 목표가 아니라 불변식이다.** `src/data/aws/data.test.ts`가 개념 640개
  전부에 문항이 하나 이상 붙어 있는지 단언하므로, 개념을 새로 더하면서 문항을 붙이지 않으면
  테스트가 깨진다. 예외 목록을 만들어 통과시키지 마라 — 그 목록이 생기는 순간 사각지대가
  되살아난다. 개념당 문항은 1개가 기본이고(640개 중 561개), 축이 양방향으로 갈리는 개념에만
  둘 이상을 붙였다.

## 디자인

- 다크모드 고정. 미니멀.
- 무채색 기반. 색은 정답/오답/중요도 표시에만 쓰되, 도식 안에서 계층을 구분할 때만 `diagram-managed`·`diagram-resource` 두 색을 예외로 허용한다(ADR-036).
- 읽는 시간이 긴 앱이다. 본문 가독성(줄간격·최대 너비)을 화려함보다 우선한다.
- 상세 규칙은 `docs/UI_GUIDE.md`.
